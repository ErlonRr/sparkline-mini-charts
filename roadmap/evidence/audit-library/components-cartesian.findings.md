# components-cartesian

## Summary
I read all six components, the core helpers they use (geometry.js, svg.js, data.js, palette.js, mini-chart-element.js), their docs and the related tests. I also cross-checked the React, Vue and Angular wrappers for these six tags. Bugs marked "confirmed" were reproduced with an in-memory fake DOM (no files written). Every component overrides render() completely and builds its own DOM once, then mutates it. That means the base class's renderChart() contract and shared style injection go unused, and about 70% of the code is copy-pasted. Line and area share around 250 identical lines, stacked and stream around 290, and the double-requestAnimationFrame clip-wipe block appears five times.

The most serious problems:
1. Stacked, stream, combo and scatter override only `get data()`, so they lose the inherited `data` setter. Assigning `el.data = ...` throws a TypeError, and the Angular directives for these four tags always do exactly that.
2. The React wrapper passes `data` as a JSON string. React 19 assigns custom-element props as properties when they exist on the element (inferred from React 19 behavior, not run here). Line and area would then store a double-encoded string and render empty, and the other four would throw.
3. Scatter crashes when the data contains a null entry.
4. All six components lose their pointer listeners after the element is disconnected and reconnected, so `interactive` stops working after moves, re-sorts or teleports.
5. `trend-color` removes the user's inline `--mini-chart-color` from the host element.
6. The parsers drop null/NaN values silently. This squeezes the x-axis and shifts hover indexes. In stacked/stream each series is filtered separately, so the values in a column no longer line up and the stacking is wrong.

The combo chart draws its bars at slot centers but its line from edge to edge, so the two don't line up.

The docs have drifted badly. The combo docs describe a data model that doesn't exist. The line/area docs point to `--mini-chart-color-1` and a `mask-line` part, and neither does anything in this group. The scatter docs give the wrong part names, CSS variables and defaults.

Theming is ad hoc. There are four different defaults for the primary color, scatter uses app-level variables (`--primary`, `--surface`), many visual constants are hard-coded, and the same concept has different names in different components. The event detail shape is different in every component and exposes internal shadow elements. Tests only check that each chart renders its basic shapes, and the fake DOM hides most of these bugs.

## Proposals
- Cartesian core rewrite: create a `CartesianSeriesElement` base with a property-first data model (private normalized model, attribute as optional JSON input, `#upgradeProperty('data')` for lazy definition), an incremental `build()/update(model)` lifecycle, and composable controllers: RevealAnimation (reduced-motion aware, capped stagger), PointerInteraction (getScreenCTM mapping, dedupe by index, keyboard nav, attached on connect), PointPool, ReferenceLine and Crosshair. Line becomes a config; area = line + fill; stacked and stream merge into one `StackedLayersElement` with `offset: none|expand|silhouette|diverging`, with stream as a preset. This removes about 1,200 duplicated LOC across the six files.
- Typed data contracts with gap support: `Series = (number|null)[]`; `MultiSeries = { name?, values: Series, color? }[]` (still accepting number[][]); combo generalized to `{ series: [{ type: 'bar'|'line'|'area', values: Series, axis?: 'left'|'right' }] }` (which makes the currently documented model real) with a `{bar,line}[]` compatibility adapter; `ScatterDatum = { x, y, r? }` with a radius scale. One normalizer module (src/core/data.js) keeps original indexes, reports discarded entries in dev mode, and is the only place input shapes are parsed.
- Geometry/scales v2: loop-based extent (no spread), a validated domain (swap or ignore invalid min/max, optional clamp/nice), a band scale for bar/line alignment, layouts that return their scales (so reference/target lines reuse them), monotone-X curve interpolation (no overshoot below the baseline), gap-aware path builders with consistent number formatting, a diverging stack offset, and optional LTTB downsampling when n far exceeds the pixel width.
- Theming system: a single token spec (`--mini-chart-color`, `--mini-chart-series-1..16`, `--mini-chart-point-radius/color/stroke`, `--mini-chart-area-opacity-start/end`, `--mini-chart-dim-opacity`, `--mini-chart-ref-*`, `--mini-chart-crosshair-*`, `--mini-chart-trend-*`, `--mini-chart-duration/easing`) defined once in a shared stylesheet (adoptedStyleSheets / constructable CSSStyleSheet shared across instances), with a single default palette constant. No host inline-style mutation (use ElementInternals custom states such as `:state(bullish)`), no non-namespaced vars, and documented `::part` names that follow one naming scheme (`point`, `point-last`, `layer-N`, `bar`, ...). Ship optional light/dark preset CSS files.
- Unified public API contract per component, generated from a custom-elements.json manifest (JSDoc @attr/@prop/@cssprop/@csspart/@fires): presence-only booleans plus enumerated attributes (`domain="shared|independent"`, `fill="gradient|solid|none"`, `trend="auto"`), consistent names (`gap` everywhere, `min`/`max` and `x-min`/`x-max`), one `curve` enum, and one `sparkline-hover` detail type `{ index, seriesIndex?, value, datum, x, y, clientX, clientY, color }`. The React/Vue/Angular wrappers, their TS types, the docs pages and a CI drift check are all generated from that manifest.
- Quality gates: real-browser component tests (Web Test Runner + Playwright, Chromium/Firefox/WebKit) with a shared edge-case matrix for each chart (empty, single, null, NaN, negative, constant, min>max, 100k values, reconnect, attribute removal, property assignment, inline-style theming, event payloads), visual regression snapshots for light/dark tokens, and framework integration tests (React 18 and 19, Vue 3.5, Angular 20+) that check data is delivered through properties.

## Findings

### [critical] components-cartesian-1: `data` property setter lost on stacked, stream, combo and scatter (getter-only override), so `el.data = ...` throws (bug)
- Evidence: src/core/mini-chart-element.js:44-51 defines get+set data; subclasses define only `get data()`: src/components/mini-stacked-area-chart.js:74-84, mini-stream-chart.js:73-83, mini-combo-chart.js:79-93, mini-scatter-chart.js:70-78. Angular always assigns the property: src/angular/mini-chart.directive.ts:235, 271, 604, 775, 847 (`if (d !== undefined) el.data = d;`). Confirmed: `Cannot set property data of #<MiniStackedAreaChart> which has only a getter` (same for Stream, Combo, Scatter).
- Detail: In JS a subclass accessor that defines only a getter shadows the whole inherited get/set pair, so the subclass property has `set: undefined`. In strict code (ES modules, Angular, React, Vue builds) the assignment throws a TypeError. Every Angular use of these four tags, through the dedicated directives or the generic MiniChartDirective, throws inside an effect and the chart never receives data. Vanilla users following the documented property API (base setter) hit the same error.
- Rec: Move parsing into a static/overridable `parseData(raw)` hook and keep a single get/set pair in the base class. Better: store the normalized model in a private field (property-first), with the attribute as optional input. Add a unit test that assigns `el.data = ...` on every component.

### [critical] components-cartesian-2: React 19 wrapper sends `data` as a JSON string; React 19 assigns it to the `data` property, double-encoding it (empty chart) or throwing (bug)
- Evidence: src/react/index.ts:231-235 (`data: typeof data === "string" ? data : JSON.stringify(data)`); base setter src/core/mini-chart-element.js:48-51 does `setAttribute("data", JSON.stringify(values))`; package.json devDependency react ^19.2.8. Confirmed for the element side: `line.data = '[1,2,3]'` gives attribute `"[1,2,3]"` and parsed data `[]`.
- Detail: React 19 sets custom-element props as properties when `prop in element`. `data` is an accessor on every chart, and the wrapper calls defineMiniChart before rendering, so the element is already upgraded. Line and area would store a JSON-encoded string and render empty; stacked, stream, combo and scatter would throw (see the previous finding). The React side is inferred from React 19's documented behavior and wasn't executed here, because node_modules isn't installed.
- Rec: Make the `data` setter accept arrays/objects and pass strings through as raw JSON. In the React wrapper pass the real array (React 19) and set it via ref/property for React 18. Add an integration test with React 18 and 19.

### [critical] components-cartesian-3: Scatter render throws on a null datum (common with JSON-serialized NaN or gaps) (bug)
- Evidence: src/components/mini-scatter-chart.js:82 `data.map((d) => Array.isArray(d) ? d[1] ?? d[0] : (d.y ?? d.x ?? 0))`; getter L70-78 returns the raw parsed array without validation. Confirmed: data="[[1,2], null, [3,4]]" gives `TypeError: Cannot read properties of null (reading 'y')`.
- Detail: The default-label computation dereferences every item before any normalization. A single `null` (which is what `JSON.stringify(NaN)` produces) makes render() throw from connectedCallback or the microtask. The shadow root stays empty on first render, and the error repeats on every attribute change.
- Rec: Validate and normalize data in the getter or parser (drop or flag invalid items) and compute the label from `normalized.length`. Add edge-case tests for null, string and object items.

### [high] components-cartesian-4: Interaction listeners removed on disconnect and never re-attached; `interactive` stops working after any DOM move (bug)
- Evidence: cleanup() detaches: mini-line-chart.js:73-76/224-227, mini-area-chart.js:80-83/255-258, stacked 58-68/178-181, stream 57-67/177-180, combo 63-73/232-235, scatter 58-64/167-170. Listeners are attached only inside #createDOM, guarded by `#initialized` (line 95-98, area 101-104, stacked 90-93, stream 89-92, combo 99-102, scatter 84-87). Confirmed: pointermove listeners 1 before disconnect, 0 after reconnect, same svg.
- Detail: The browser fires disconnected then connected whenever an element is moved: keyed list reorders in React/Vue/Angular, sorting tables, Teleport/KeepAlive, CDK drag-drop. After that the chart renders fine but hover and events are dead.
- Rec: Attach listeners in connectedCallback (or once in the constructor on the shadow root, since it survives moves) and only cancel timers/rAF on disconnect. Better: a shared InteractionController with connect()/disconnect(). Add a reconnect test.

### [high] components-cartesian-5: `trend-color` logic deletes the user's inline `--mini-chart-color` on the host and leaves a stale value when data becomes empty (theming)
- Evidence: mini-line-chart.js:282-292 and mini-area-chart.js:334-344: `else { this.style.removeProperty("--mini-chart-color"); }` runs on every render without trend-color=auto; the empty-data early return (line 256-264, area 306-315) skips the cleanup. Confirmed: a user-set inline `--mini-chart-color: red` becomes "" after the first render; with trend-color=auto, then data=[], the inline bullish var stays.
- Detail: Inline host styles belong to the consumer. React `style={{'--mini-chart-color': c}}`, Vue `:style` and plain `style="..."` are wiped on the first render, so per-instance theming silently fails. Mutating the host `style` attribute also fights framework reconciliation (React re-applies style only when the prop changes, so the color disappears until then) and causes SSR/hydration diffs.
- Rec: Never write to the host's inline style. Express trend through internal state: ElementInternals custom states (`:host(:state(bearish))`), an internal wrapper `<g>` with its own CSS var, or a reflected internal attribute. Fall back to `--mini-chart-color` when trend isn't active.

### [high] components-cartesian-6: Invalid values are silently dropped, compressing the x-axis; in stacked/stream each series is filtered separately, so columns no longer line up (data-model)
- Evidence: src/core/data.js:17 `parsed.filter(...)`; stacked 78-80 and stream 77-79 `series.filter(Number.isFinite)`; geometry.js:382,393 `series[j][i] || 0`; combo 83-89 drops whole items. Confirmed: stacked data [[1,null,3],[2,2,2]] parses to [[1,3],[2,2,2]] (value 3 is stacked at time index 1 and index 2 becomes 0).
- Detail: Time series with gaps are normal (`JSON.stringify(NaN)` produces null). Line/area plot [1,null,3] as a 2-point line over the full width, and hover `index` refers to the filtered array, not the consumer's array. For stacked/stream the stacking is numerically wrong. There's no gap rendering and no developer warning.
- Rec: Normalize to `(number|null)[]` while keeping positions. Render gaps as path breaks (`M`) or skip points. Stack with null treated as 0 at the same index. Report original indexes in events. Emit a dev-mode console.warn for discarded input.

### [high] components-cartesian-7: Combo chart: bars sit at slot centers but line points span edge to edge, so bars and line don't align (bug)
- Evidence: mini-combo-chart.js:274-285 combine createBarLayout + createCartesianLayout; geometry.js:61 (line x = padding + i*(w-2p)/(n-1)) vs geometry.js:159-165 (bar x = padding + slot*i + (slot-barWidth)/2). Confirmed for n=5: bar centers 11.6, 30.8, 50, 69.2, 88.4 vs line x 2, 26, 50, 74, 98.
- Detail: The component exists to show two measures on a synchronized time axis, but only the middle point lines up. The crosshair and hover index snap to line x, so on the edges the highlighted index is visually over the wrong bar.
- Rec: Introduce a band scale in geometry (`createBandScale` returning center(i)) and let createCartesianLayout accept `xMode: 'band'|'edge'`. Combo should use band centers for the line, and hover should use the same scale.

### [high] components-cartesian-8: Pointer to index mapping ignores preserveAspectRatio="xMidYMid meet" letterboxing (bug)
- Evidence: src/core/svg.js:96 `preserveAspectRatio: "xMidYMid meet"`; mini-line-chart.js:172-175, mini-area-chart.js:203-206, mini-combo-chart.js:181-184 use `(clientX - rect.left) / rect.width * chartWidth`. README.md:134-137 recommends `inline-size: 12rem; block-size: 3rem` (4:1 vs viewBox 10:3).
- Detail: When the host's aspect ratio differs from the viewBox, the drawing is centered with side margins, but the math assumes the viewBox fills the whole rect. With the README sizing the offset reaches about 8 viewBox units at the edges (about 4 indices for 50 points), so the crosshair and event index don't match the cursor.
- Rec: Convert with `svg.getScreenCTM().inverse()` and DOMPoint, or move the whole library to `preserveAspectRatio="none"` with non-scaling strokes (usually preferred for sparklines, and the strokes already use vector-effect).

### [high] components-cartesian-9: Docs describe APIs that don't exist (combo data model, line/area color var, scatter parts and vars) (docs)
- Evidence: docs/components/mini-combo-chart.md:6-28,37-44 (`[{type, values}]`, area type, part=layer) vs mini-combo-chart.js:79-93 (`{bar,line}[]`); mini-line-chart.md:18,24 and mini-area-chart.md:18 (`--mini-chart-color-1`, `mask-line`) vs svg.js:7/line chart using `--mini-chart-color`; mini-scatter-chart.md:24,32-37 vs mini-scatter-chart.js:104-110,129-130,192; docs/getting-started.md:162; README.md:150 (#0ea5e9).
- Detail: Users copying documented examples get an empty combo chart, color tokens with no effect on line/area/scatter, and `::part(circle)` / `::part(trendline)` selectors that match nothing. Most of the real attributes (curve, points, min, max, reference-value, trend-color, gradient, normalize, shared-domain, bar-gap, interactive) and every event aren't documented. The stacked docs recommend `::part(layer):nth-child()`, which CSS doesn't allow (the real hook is `::part(layer-2)`).
- Rec: Generate docs, wrapper prop types and d.ts from one per-component metadata manifest (custom-elements.json via @custom-elements-manifest/analyzer plus JSDoc @attr/@cssprop/@csspart/@fires tags). Add a CI check that diffs the manifest against observedAttributes.

### [high] components-cartesian-10: `sparkline-hover` has five different detail shapes, exposes internal shadow elements, and reports untheamed colors (api)
- Evidence: line 201-205 / area 232-236 `{index,value,x,y}`; combo 205-215 `{index,barValue,lineValue,x,y}`; stacked 158-162 / stream 157-161 `{layerIndex,seriesData,color,element}`; scatter 147-151 `{index,data,element}`; color from `getSegmentColor(layerIndex)` (stacked 156) ignores `--mini-chart-color-N`. Confirmed: stacked detail color `#84cc16` regardless of theme. React types it as a bare `CustomEvent` (src/react/index.ts:32-37).
- Detail: The same event name with different payloads blocks a typed multi-framework API and makes generic tooltip code impossible. `element` is composed out of the shadow root and couples consumers to internal DOM. x/y are viewBox units with no clientX/clientY, so tooltips can't be positioned without reimplementing the scale.
- Rec: Define one `SparklineHoverDetail<T>` = `{ index, seriesIndex?, value, datum, x, y, clientX, clientY, color }`, with color resolved via getComputedStyle. Drop `element`. Export the type and map it in all wrappers. Document per-chart datum types.

### [high] components-cartesian-11: Boolean attribute conventions are inconsistent and the wrappers can't express `false` for default-true flags (api)
- Evidence: combo L264 `shared-domain` default true unless the string "false"; area L380-381 `gradient` default on unless "false"; scatter L200 trend-line presence but "false" disables; stacked L233 `normalize` and `interactive` presence-only. React wrapper L258-260 omits false booleans; Angular syncAttr L34-40 removes on false; Angular combo L587/608 `sharedDomain` default false gives a removed attribute.
- Detail: `<MiniComboChart sharedDomain={false}>` (React) and `[shared-domain]="false"` (Angular) both remove the attribute, so the domain stays shared. `<MiniAreaChart gradient={false}>` in React keeps the gradient. HTML boolean semantics (presence = true) are broken by the string-"false" checks, and `interactive="false"` / `normalize="false"` still enable the feature.
- Rec: Adopt presence-only booleans everywhere. Turn default-true options into enumerated attributes (`domain="shared|independent"`, `fill="gradient|solid|none"`) or negative flags. Have wrappers emit explicit enumerated values. Add a shared `readBooleanAttr` / `readEnumAttr` helper.

### [high] components-cartesian-12: Scatter reads app-level `--primary` / `--surface` variables (theming)
- Evidence: src/components/mini-scatter-chart.js:104 `color-mix(in srgb, var(--primary, #3b82f6) 40%, transparent)`, :111 `var(--surface, #ffffff)` (also mini-bullet-chart.js:108-110).
- Detail: Custom properties inherit into shadow DOM, so any host app defining `--primary` / `--surface` (shadcn/ui, Bootstrap 5, Material, Tailwind themes) silently restyles the chart. With shadcn's `--primary: 222.2 47.4% 11.2%` (an HSL triplet, not a color) the color-mix is invalid at computed-value time, so the stroke falls back to its initial value (none) and the trend line disappears.
- Rec: Only consume `--mini-chart-*` tokens. Map them to the app in user-land (`--mini-chart-trend-color: hsl(var(--primary))`). Add a lint/grep check in CI forbidding `var(--` without the `mini-chart` prefix.

### [high] components-cartesian-13: About 70% duplicated code; all six bypass the base render contract (architecture)
- Evidence: Identical blocks: line 78-88/91-105/169-227/234-245/329-376/378-401 vs area 85-111/200-258/264-275/433-480/482-507; stacked vs stream are ~97% identical (303 vs 299 LOC). The 2×rAF + 850 ms clip-wipe block is repeated in line 384-398, area 490-504, stacked 281-295, stream 277-291, combo 359-366. Base `render()`/`renderChart()` (mini-chart-element.js:83-114) is overridden and never used; the style preamble is copied per file.
- Detail: Every fix (reconnect, theming, gaps, a11y) has to be applied five or six times. Drift between copies already exists: area's `[part="crosshair"]` lacks pointer-events:none (area 123-124 vs line 117-118), stacked/stream omit the aspect-ratio var, combo resets its timer differently. The base class gives almost nothing, so the next 'component' will copy again.
- Rec: Introduce an incremental-render base (`build()` once, `update(model)`), plus reusable controllers: RevealAnimation, PointerInteraction, PointPool, ReferenceLine, and a shared `buildCurvePath(points, curve, {gaps})`. Merge stacked and stream into one `StackedLayersElement` with `offset`, and make area a line with fill.

### [medium] components-cartesian-14: Domain edge cases: min>max or a one-sided bound beyond the data inverts or overflows the chart; points and reference line aren't clipped (bug)
- Evidence: geometry.js:31-46 createDomain doesn't validate min/max; line 266-276, area 317-328 pass raw parseFloat values; points group and reference line sit outside the clip group (line 145-163, area 173-194); svg.js:20 `overflow: visible`. Confirmed: min=10,max=0 gives an inverted chart; min=5 on [1,2,3] gives domain [5,3] and y = -24, -11, 2 (outside the viewBox). Scatter instead coerces max ≤ min to [min, min+1] (geometry.js:784-786).
- Detail: A wrong bound silently renders upside down or bleeds over neighboring content (overflow visible) while the line itself is clipped, so the dots and the line disagree. The reference line outside the domain is also drawn outside the chart. Line and scatter handle invalid bounds differently.
- Rec: Validate bounds in one place (swap or ignore and warn). Offer a `clamp` option. Clip points, the reference line and the trend line with the same clipPath (padded by the point radius). Return the yScale from layouts so the reference line reuses it instead of the duplicated formula at line 297-298 / area 349-350.

### [medium] components-cartesian-15: Large arrays: Math.min/max spread overflows the stack; linear stagger delays and per-point forced reflows (perf)
- Evidence: geometry.js:32-33, 778-781 `Math.min(...values)`; combo 321 `${index * 0.03}s`, 333 timer; scatter 252 `${index * 0.02}s`, 257; line 370 / area 474 `circle.getBoundingClientRect()` inside the loop. Confirmed: createCartesianLayout(200k values) throws `RangeError: Maximum call stack size exceeded` (120k is OK).
- Detail: Beyond about 125k values every Cartesian chart crashes. With 1,000 points the combo's last bar appears after about 30 s and scatter takes about 20 s. With points="all" the first render forces one layout per circle. Under prefers-reduced-motion only the durations are zeroed (svg.js:55-62), so stagger delays still apply.
- Rec: Compute min/max with a loop. Cap total stagger (for example delay = i/n × 400 ms). Batch writes and do one reflow. Optionally downsample (LTTB) when n far exceeds the pixel width. Honor reduced motion in JS (`matchMedia`) and add an `animation="none"` attribute.

### [medium] components-cartesian-16: Stacked/stream: negative values overlap layers; a single time point renders nothing; flat arrays silently empty (bug)
- Evidence: geometry.js:385-404 stacks negatives on the same running total and normalizes only when `sum > 0` (L394); geometry.js:415 x = width/2 for every point when numPoints===1; stacked/stream getters map non-array rows to []. Confirmed: [[5,5],[-3,-3]] gives layer 1 y0/y1 of 2 → 17.6, overlapping layer 0; [[5],[3]] gives a single x=50 (zero-width polygon).
- Detail: Negative values produce overlapping layers instead of a diverging stack. With normalize, columns whose sum is ≤ 0 aren't normalized while the rest are, so different columns use different scales. One-sample series are invisible. Passing `[1,2,3]` renders nothing, and the default label says 'Stacked-area chart with 3 values'.
- Rec: Implement a diverging offset (positives up, negatives down) or clamp with a warning. Render single samples as full-width bands or bars. Accept a 1D array as a single series and base the label on series × points.

### [medium] components-cartesian-17: Scatter: invalid items become phantom points; flat Y data sits on the bottom edge; bubble radius unscaled (data-model)
- Evidence: geometry.js:772 `return { x: index, y: 0, r: pointRadius }` for invalid items, and the same fallbacks at L760-766; L784-786 `[min, min+1]` for equal values vs createDomain's ±10% padding (geometry.js:40-43); r taken raw from data (L762, 767). Confirmed: [[1,2],"x",[3,4]] draws an extra point at (4,26); constant Y gives y=26 for all points (line charts center at 15).
- Detail: Garbage input creates fake points that also bend the domain and the regression line. Constant series render differently from the line family. Bubble r is in raw viewBox units (r=50 covers the chart; a negative r is invalid SVG) and isn't area-scaled.
- Rec: Skip invalid items but keep their original indexes. Reuse createDomain for both axes. Add a radius scale (sqrt over [rMin, rMax], attributes `min-radius` / `max-radius`) and clamp r ≥ 0.

### [medium] components-cartesian-18: Hard-coded visual constants and inconsistent token names prevent a real theming system (theming)
- Evidence: Gradient stop opacities 0.45/0.02 and 0.55/0.05 (area 144-149, 406, 414-419); area solid opacity 0.2 inline (383); active-point `stroke: white` (line 118, area 124); radii 1.75 (line 311/353), 2.5 (line 159), 2 (combo 381), 3 (scatter 192); hover dim 0.45 and brightness 1.18/1.2/1.25 (stacked 115-120, combo 139-140, scatter 119-125); durations .4s/.8s/850 ms everywhere. Point color tokens differ: `--mini-chart-point-fill` (svg.js:38) vs `--mini-chart-point-color` (scatter 110) vs `--mini-chart-color` (combo 130). Primary fallbacks: #2563eb (svg.js:7, combo 124), #3b82f6 (scatter 104/110, docs), #0ea5e9 (README:150).
- Detail: Dark mode breaks the white active-point ring. Designers can't tune area opacity, point size, hover emphasis or motion without `::part` hacks. The same concept has three token names and four default colors. `trend-color` (attribute, bullish/bearish) and `--mini-chart-trend-color` (scatter regression line) mean different things.
- Rec: Publish a token spec in one `tokens.js` / CSS layer, for example: `--mini-chart-color`, `--mini-chart-series-1..16`, `--mini-chart-point-radius`, `--mini-chart-point-color`, `--mini-chart-point-stroke`, `--mini-chart-area-opacity-start/end`, `--mini-chart-dim-opacity`, `--mini-chart-duration`, `--mini-chart-easing`. Use `r: var(--mini-chart-point-radius)` (r is a CSS property in SVG2). Keep a single default color constant and rename the attribute to `trend="auto"`.

### [medium] components-cartesian-19: Morph animations only work when path structure matches; `d` transitions are unsupported in Safari (bug)
- Evidence: Padded morph builds only `L` commands (line 403-417, area 509-531) while smooth/step use C/H/V (geometry.js:80-144); stacked/stream switch to inline `d .4s` without padding (stacked 264-267, stream 261-264); combo recreates the point each render (375-385) despite the cx/cy transition at 129-133.
- Detail: With curve=smooth/step, or with stacked/stream data whose length changes, CSS can't interpolate and the path jumps. In WebKit the CSS `d` property isn't supported, so there's no morph at all. The library behaves differently across browsers and curve modes.
- Rec: Either drop path morphing (keep the entry reveal plus opacity) or implement a JS tween (rAF interpolation of resampled points with the same command count), shared by all Cartesian charts and disabled under reduced motion.

### [medium] components-cartesian-20: Curve vocabulary and wrapper prop types disagree with the implementation (api)
- Evidence: line/area accept step/step-after/step-before (line 237-239); stacked only `smooth` (190); stream treats every value other than "linear" as smooth (189); combo smooth|linear (348-350). React types: `curve?: "linear"|"smooth"|"step"` for all and `points?: "none"|"all"|"last"|"ends"` (src/react/index.ts:51-52, 70-71, 82, 87, 156). "ends" doesn't exist and "min-max" is missing.
- Detail: `curve="step"` is valid in the types but renders smooth in stream and linear in stacked/combo. `points="ends"` renders nothing. Line and area also have different `points` defaults (last vs none).
- Rec: Define one `CurveType` enum handled by a single `buildCurvePath()` (with monotone-X instead of Catmull-Rom to avoid overshoot below the baseline) used by every Cartesian chart. Generate wrapper types from the manifest.

### [medium] components-cartesian-21: Interaction robustness and accessibility gaps (a11y)
- Evidence: Hover dispatched on every pointermove even when the index is unchanged (line 201, area 232, combo 205; confirmed 3 events for 3 moves on index 0). No pointercancel / touch-action. Crosshair stays visible when `interactive` is removed mid-hover (line 209, area 240, combo 219) or when data empties (line 256-264). Stacked/stream/scatter fire leave only on svg exit (stacked 175). No tabindex, keyboard navigation or live region anywhere (svg role=img, svg.js:93).
- Detail: Event floods hurt framework re-renders (each hover triggers setState). On touch devices the crosshair can stick after the browser takes over for scrolling. Keyboard and screen-reader users have no access to values, and the default label ('Line chart with 7 values') gives no summary such as min, max or last value.
- Rec: Dispatch only when the index changes. Handle pointercancel and set `touch-action: pan-y`. Hide hover state whenever interactive or data changes. When interactive, make the host focusable with arrow-key navigation and aria-activedescendant or a live region. Generate a richer default label (range, last value, trend).
