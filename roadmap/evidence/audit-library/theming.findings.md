# theming

## Summary
The theming system grew up ad hoc and is not yet a design-token system. There are about 51 distinct `--mini-chart-*` custom properties spread across 17 shadow stylesheets. Each one carries its own literal fallback, so the default accent alone is #2563eb in one place, #3b82f6 in another, #10b981 for bar positives, and #0ea5e9 according to the README. The README and docs correctly name only about 14 of these tokens. Seven component pages and getting-started tell users to set `--mini-chart-color-1` on single-series charts that never read it, several documented tokens and parts do not exist, and the demo advertises 5 phantom tokens that no component reads (inactive-opacity, hover-brightness, transition-duration, hover-duration, trendline-color). Two defects affect visible behavior in normal use. First, under prefers-reduced-motion the shared `* { stroke-dashoffset: 0 !important }` rule draws every progress and radial-bar value as 100%, and because it is an `!important` rule inside the shadow root, users cannot fix it from outside. Second, the React wrapper JSON-encodes `style` and turns `className` into `class-name`, so per-instance theming in React crashes or does nothing. Several more high-impact problems: `trend-color` writes to the host's inline style and, on every render, erases a user-supplied inline `--mini-chart-color`. `gradient="false"` (the value Angular and Vue emit for `false`) makes the bullet measure black and the progress arc invisible. Fallbacks read the app's own `--primary`/`--surface` variables, which turns bullet bands black and hides the scatter trendline in shadcn-style apps. Some tokens mean different things in different charts: `--mini-chart-stroke-width` is 2 screen px for lines but 14 or 12 user units for gauge and progress arcs, and `--mini-chart-range-color` is a background band in bullet but the main bar fill in range-bar. Per-series colors are inline `var(--mini-chart-color-N, <palette hex>)` styles in only 5 components. The 16-color fallback cycles independently of the user's tokens. Radial-bar gradients and all hover events report raw palette hex, ignoring the user's tokens. There is no dark-mode default, no forced-colors handling, no shipped preset file, no theme API and no token layer, which is why the demo redefines 28 tokens twice and drives presets and gradients by setting inline styles and attributes element by element. Gradients (v1.4.0) are per-instance `<linearGradient>` elements with Math.random ids, configured only through a `gradient` attribute. That attribute is parsed by 5 copy-pasted ad hoc parsers, its defaults are hard-coded hex values disconnected from the tokens, and it cannot be themed from CSS. Shadow-part names are inconsistent (`track` means three different things, `bar` is a stroked tick in OHLC). Candlestick and OHLC do not expose bullish/bearish parts, and the docs describe at least 12 parts that do not exist. The default palette has 8 of 16 colors below 3:1 contrast against white and near-duplicate hues that collapse under deuteranopia (ΔE about 3).

## Proposals
- TARGET TOKEN TIERS. Tier 1 (global/base, set on :root or a container): --mini-chart-color (accent; keep this name to limit churn), --mini-chart-surface (halo and background behind markers), --mini-chart-foreground (labels), --mini-chart-muted (greys for track, grid and baseline), --mini-chart-series-1..12, --mini-chart-line-width, --mini-chart-radius, --mini-chart-font-family, --mini-chart-duration, --mini-chart-easing. Tier 2 (semantic): --mini-chart-positive, --mini-chart-negative, --mini-chart-neutral, --mini-chart-success, --mini-chart-warning, --mini-chart-danger, --mini-chart-track, --mini-chart-reference, --mini-chart-crosshair, --mini-chart-highlight; state tokens --mini-chart-dim-opacity, --mini-chart-hover-brightness, --mini-chart-focus-ring. Tier 3 (component, named after the part): --mini-gauge-arc-width, --mini-progress-arc-width, --mini-bullet-band-1..3, --mini-bullet-target, --mini-candlestick-wick-width, --mini-ohlc-tick-width, --mini-range-bar-fill, --mini-range-bar-marker, --mini-scatter-trendline, --mini-combo-bar. Each tier-3 token defaults to tier 2, which defaults to tier 1, which defaults to one literal.
- SINGLE RESOLUTION POINT INSIDE THE SHADOW ROOT. One shared base stylesheet (an adopted CSSStyleSheet) declares private vars once per tier on :host, for example `--_accent: var(--mini-chart-color, light-dark(#2563eb,#60a5fa)); --_positive: var(--mini-chart-positive, var(--mini-chart-bullish-color, …))`. Each component sheet maps its parts only to `var(--_…)`. No literal colors appear in component files. A CI grep rejects `#hex`, `rgb(` and un-prefixed var() in src/components.
- NAMING CONVENTION. Prefix --mini-chart- for shared tokens and --mini-<chart>- for component tokens. Colors carry no suffix (--mini-chart-positive); non-colors carry a unit suffix (-width, -opacity, -radius, -duration, -size). Component token segments must equal ::part names. Series tokens are --mini-chart-series-N, never --mini-chart-color-N. Private implementation vars use --_ and are never documented.
- SERIES COLOR MODEL. JS assigns each series element `part="<mark> series series-N"` and an inline private var `--_series: var(--_series-N)`, where the base sheet defines `--_series-N: var(--mini-chart-series-N, <default N>)` for N = 1..12. The cycle length comes from a `series-count` attribute or theme (default 12) and is applied with modulo in JS, so user palettes wrap with their own colors. Event detail colors are resolved with getComputedStyle. Gradient defaults derive from series and accent tokens. Every multi-series chart (pie, half-pie, stacked, stream, radial, combo, gauge zones, bullet bands) uses the same mechanism.
- STATE WITHOUT HOST MUTATION. Use ElementInternals CustomStateSet (`:host(:state(trend-up|trend-down|empty|interactive))`) with a fallback class on the internal svg. trend-color=auto maps `--_accent` to `--_positive`/`--_negative` in CSS. Remove every `this.style.*` write on the host. Per-instance attributes (radius, wick-width, gradient stops) become private inline vars on internal nodes, recomputed each render, with precedence attribute > component token > semantic token > default.
- SHIPPED PRESETS AS OPTIONAL CSS (package exports `sparkline-mini-charts/themes/*.css`). light.css and dark.css set tier 1/2 on `:root, [data-mini-chart-theme=light|dark]`. auto.css uses `color-scheme: light dark` with light-dark() and a `@media (prefers-color-scheme)` fallback. high-contrast.css is `@media (forced-colors: active)`: accent CanvasText, positive and negative as distinct system colors plus dash patterns, track GrayText, active Highlight, dimming replaced by outlines. okabe-ito.css is a colorblind-safe series palette. Built-in defaults inside the components stay neutral and must pass at least 3:1 against both #fff and #0f172a.
- MOTION AS TOKENS. Replace the `*{… !important}` block with `--_dur: var(--mini-chart-duration, 400ms)` and `--_stagger: var(--mini-chart-stagger, 30ms)`, used in every transition and delay. `@media (prefers-reduced-motion: reduce){:host{--_dur:0ms;--_stagger:0ms}}` plus a `motion="auto|reduce|full"` attribute. Hard rule: never override data-encoding properties (stroke-dashoffset, d, width/height) in motion CSS.
- GRADIENTS AS FIRST-CLASS, THEMABLE PAINT. Add a core/gradient.js shared by all charts: a strict attribute grammar (boolean | JSON array of colors | array of {offset,color}); default stops `var(--mini-chart-gradient-1..3)`, which fall back to accent/series or success→warning→danger for gauge; stop-color set through the style property so var() works; documented direction and opacity tokens (--mini-area-fill-opacity-start/end); deterministic local ids. A theme can then define gradients without touching markup.
- OPTIONAL JS THEME API (tree-shakeable entry `sparkline-mini-charts/theme`). `type MiniChartTheme = { color, surface, muted, positive, negative, neutral, success, warning, danger, series: string[], gradients?: {...}, motion?: {...} }`. `themeToCSS(theme, selector)` returns a CSS string for SSR or build steps. `applyTheme(theme, target = document.documentElement)` sets custom properties. `MiniChartCSSProperties` type augments React.CSSProperties with token keys. Thin wrappers: React `<MiniChartTheme theme>` (a display:contents element with the vars), Vue `<MiniChartTheme>`, Angular `[miniChartTheme]` directive. CSS stays the source of truth; JS only serializes.
- STANDARD ::part VOCABULARY AND MANIFEST. Use one cross-chart vocabulary (svg, plot, line, area, bar, point, segment, arc, track, band, marker, needle, label, reference-line, crosshair, baseline, trend-line; modifiers positive, negative, neutral, series-N, first, last, min, max, active). Annotate classes with @csspart/@cssprop/@attr and generate custom-elements.json, from which the docs tables, VS Code CSS custom data and React/Vue/Angular prop types are produced. CI fails when src and manifest diverge. Guidance in the docs: custom properties are for theme-wide values, ::part for structural one-off overrides; no inline paint or !important inside shadow roots.
- MIGRATION PLAN. v1.5 (non-breaking): introduce the new names as primary and chain the old ones as fallbacks (`--_positive: var(--mini-chart-positive, var(--mini-chart-bullish-color, var(--mini-chart-win-color, …)))`). Add new part names alongside the old ones. Fix the critical and high bugs (reduced motion, React style/className, gradient="false", trend-color, --primary/--surface leakage). Publish a mapping table: color-N→series-N; bullish/positive/win→positive; bearish/negative/loss→negative; tie/muted→neutral; safe→success; warn/warning→warning; danger→danger; track-color/track-bg→track; ref-color/width→reference(-width); stroke-width→line-width (lines) or gauge/progress-arc-width; range-color→bullet-band or range-bar-fill; range-1..3→bullet-band-1..3; bar-opacity-inactive→dim-opacity; trend-color (scatter)→scatter-trendline; point-fill/point-color→point; point-stroke/marker-color→surface; fill/segment-color→removed (use series or ::part). Optionally emit a one-time dev-mode console notice. v2.0: remove the legacy fallbacks, legacy part names, `SEGMENT_COLORS` and color attributes such as win-color.
- VERIFICATION BACKLOG FOR THEMING. Playwright tests that assert computed fill/stroke for every token in the manifest, at default and with a preset. Screenshot baselines for light, dark, forced-colors (emulateMedia forcedColors) and reduced-motion. A contrast and CVD validator script for palettes run in CI. A wrapper test matrix checking that React style/className, Vue :style/class and Angular [style.--x] bindings reach the host unchanged.

## Findings

### [critical] theming-1: prefers-reduced-motion rule draws every progress and radial-bar value as 100% (bug)
- Evidence: src/core/svg.js:55-62 `*, *::before, *::after { ... stroke-dashoffset: 0 !important; }`; src/components/mini-progress-chart.js:147-153 (pathLength 100, dasharray 100), :282,:290,:294,:298 (value encoded as inline strokeDashoffset); src/components/mini-radial-bar-chart.js:267-271, :293, :323, :354
- Detail: Progress and radial-bar encode the data value as stroke-dashoffset on a pathLength=100 arc. The shared reduced-motion block forces stroke-dashoffset to 0 with !important, so any value above 0 renders as a full arc (progress hides only at exactly 0 via opacity). Every user with OS-level Reduce Motion sees wrong data. Under the cascade, an !important declaration inside a shadow tree beats outer declarations, so authors cannot fix it even with ::part(...) !important.
- Rec: Remove `stroke-dashoffset` (and any other geometry or data property) from the motion block. Replace the blanket `*` rule with private duration tokens (`:host{--_dur: var(--mini-chart-duration, 400ms)} @media (prefers-reduced-motion: reduce){:host{--_dur:0ms;--_stagger:0ms}}`) and use `var(--_dur)` in every transition. Add a regression test that renders progress/radial with matchMedia mocked to reduce and asserts the final dashoffset.

### [critical] theming-2: React wrapper breaks `style` and `className`, so per-instance theming is impossible in React (bug)
- Evidence: src/react/index.ts:242-264: every object prop is `JSON.stringify`-ed (`style` becomes a JSON string) and every camelCase key is kebab-cased (`className` → `class-name`)
- Detail: `<MiniLineChart style={{'--mini-chart-color':'#f00'}} />` passes a string `style`, and React DOM throws ('The `style` prop expects a mapping…'). `className` becomes an unknown `class-name` attribute, so class-based themes never match. These are the two standard ways React apps apply CSS custom properties per component.
- Rec: Allow-list pass-through props (`style`, `className`, `id`, `slot`, `aria-*`, `data-*`, `ref`, `key`, event handlers) before the kebab/JSON conversion, and convert only the chart's declared attribute props. Add tests that render with style/className and assert the resulting attributes.

### [high] theming-3: `trend-color` writes the host's inline style and erases user-supplied `--mini-chart-color` (theming)
- Evidence: src/components/mini-line-chart.js:282-292 and src/components/mini-area-chart.js:334-344: `this.style.setProperty('--mini-chart-color', …)` / `else this.style.removeProperty('--mini-chart-color')` on every render
- Detail: (1) When `trend-color` is not `auto`, each render calls removeProperty, which deletes `style="--mini-chart-color: …"` set by the user or by Angular `[style.--mini-chart-color]` / Vue `:style`. (2) When it is `auto`, the inline host style outranks every author stylesheet rule. (3) It mutates the `style` attribute that frameworks own, so a framework re-patch wipes the trend color, and the logic is duplicated in two files.
- Rec: Never touch the host's style. Compute the trend inside the shadow root: set CustomStateSet via ElementInternals (`:host(:state(trend-up))`) or a class on the internal svg, and map it in CSS: `:host(:state(trend-up)){--_accent: var(--mini-chart-positive, …)}`. Extract the logic into a shared mixin or helper.

### [high] theming-4: gradient="false" (what Angular and Vue emit) turns the bullet measure black and makes the progress arc invisible (bug)
- Evidence: src/components/mini-bullet-chart.js:118-120 `:host([gradient]) [part="measure"]{fill:unset}` + :195 ("false" → null) + :290 (`style.fill=""`); src/components/mini-progress-chart.js:110-112 `:host([gradient]) [part="value"]{stroke:unset}` + :207 + :274; src/angular/mini-chart.directive.ts:43-50 (`JSON.stringify(false)` → "false")
- Detail: The `:host([gradient])` rules match on attribute presence, but the JS treats "false" as off and clears the inline paint. `unset` then inherits from the svg: fill defaults to black, stroke to none. Angular `[gradient]="false"` and Vue `:gradient="false"` (Vue 3 sets non-boolean attributes to the string 'false') both trigger it. The v1.4.0 changelog entry 'fill and stroke precedence on bullet and progress gradients' introduced these rules.
- Rec: Remove the `:host([gradient])` rules. Apply gradient paint through a private custom property (`--_measure-paint: url(#g)`, CSS `fill: var(--_measure-paint, var(--_accent))`) so absence and "false" fall back naturally. Normalize boolean parsing in one shared helper (null/'false' = off). Add tests for gradient="false".

### [high] theming-5: Host `color` is always overridden, and only some parts follow it: the 'currentColor' theming story is false and inconsistent (theming)
- Evidence: src/core/svg.js:7 `:host{ color: var(--mini-chart-color, #2563eb) }`; direct `var(--mini-chart-color, …)` instead of currentColor in bar:82, combo:124,130, progress:105, bullet:112, scatter:110, range-bar:104,112, gauge:132; demo claim at demo/index.html:2715-2729
- Detail: Because :host declares `color`, the parent's `color` never inherits, so `.card.success { color: … }` (the demo's 'Zero-config' level 1) has no effect. Setting `color` directly on the element recolors line, area and candles (currentColor) but not bars, combo, progress, bullet, scatter, range-bar or the gauge needle. The fallback accent also differs by chart: #2563eb (svg, combo, gauge), #3b82f6 (bullet, progress, scatter, range-bar), #10b981 (bar positives). The README says #0ea5e9 (README:150).
- Rec: Define a single private accent on :host (`--_accent: var(--mini-chart-color, currentColor)` or one documented default) and use it everywhere. Decide explicitly whether the charts inherit text color, and document that decision. Remove all per-component literal accents.

### [high] theming-6: Fallbacks read the host app's un-namespaced `--primary` / `--surface` variables (theming)
- Evidence: src/components/mini-bullet-chart.js:108-110 `color-mix(in srgb, var(--primary, #3b82f6) …)`; src/components/mini-scatter-chart.js:104 (`--primary`), :111 `var(--surface, #ffffff)`; the demo defines both (demo/index.html:63,68)
- Detail: These generic names are common in app design systems. In shadcn/ui v3, `--primary` is raw HSL channels (`222.2 47.4% 11.2%`), which makes `color-mix()` invalid at computed-value time. Bullet range bands then become `fill: unset` (black), and the scatter trendline becomes `stroke: unset` (none, invisible). In the demo, the scatter trendline silently picks up the demo's violet.
- Rec: Never reference un-namespaced variables. Route through library tokens (`--mini-chart-accent`, `--mini-chart-surface`) with literal fallbacks, and add a lint rule (grep in CI) rejecting `var(--` names that lack the `--mini-` or `--_` prefix.

### [high] theming-7: Token semantic collisions break theming at :root (theming)
- Evidence: --mini-chart-stroke-width: svg.js:28 (2, non-scaling screen px), gauge:129 (14 user units), progress:100,106 (12); --mini-chart-range-color: bullet:104 (background band rgba .15) vs range-bar:104 (main bar fill); `track`: --mini-chart-track-color for progress and radial, gauge ignores it; README:152 'lines, wicks, and arcs'; demo app.js:1044 writes `${stroke}px`
- Detail: architecture.md:34 recommends setting tokens on a dashboard root. Doing so with `--mini-chart-stroke-width: 2.5` shrinks gauge and progress arcs from 14/12 to 2.5 units, and setting `--mini-chart-range-color` to color range bars also paints every bullet background band. One name carries different units and meanings depending on the chart.
- Rec: Give each concept its own name: `--mini-chart-line-width` (non-scaling px), `--mini-gauge-arc-width` and `--mini-progress-arc-width` (user units), `--mini-bullet-band-1..3`, `--mini-range-bar-fill`. Keep the old names only as fallbacks in v1.x.

### [high] theming-8: Docs and README describe tokens that don't apply and omit about 37 that do (docs)
- Evidence: `--mini-chart-color-1` documented as the main color for single-series charts that never read it: docs/components/mini-line-chart.md:18,32, mini-area-chart.md:18,31, mini-bar-chart.md:18-19, mini-bullet-chart.md:25, mini-combo-chart.md:37-52, mini-range-bar-chart.md:30,44, mini-scatter-chart.md:32,46, docs/getting-started.md:162; README:142 `--mini-chart-fill` example (no effect on pie); README:150 default #0ea5e9 (actual #2563eb); README:156 track rgba(0,0,0,.08) (actual rgba(128,128,128,.15/.18)); progress.md:20-21 wrong defaults; scatter.md:33 `--mini-chart-trendline-color` (actual --mini-chart-trend-color); bullet.md:26-28 safe/warn/danger bands (bullet uses range-1..3); stacked/stream docs defaults #3b82f6/#10b981/#f59e0b (actual palette #84cc16/#f43f5e/#0ea5e9); bar.md:19 contains leftover text 'Wait, typically negative is red.'
- Detail: Users who copy the official examples get no effect (for example, line.md's `style="--mini-chart-color-1:#10b981"`). About 37 consumed tokens appear nowhere in the docs (point-fill, ref-*, crosshair-*, positive/negative, needle, measure, target, value, text, range-*, bar-color, gap-*, wick/tick-width, marker-*, point-*, trend-*, baseline, muted, warning). The demo advertises 5 tokens that no component reads.
- Rec: Make the source the single source of truth: add JSDoc `@cssprop`/`@csspart` tags, generate custom-elements.json (CEM analyzer), and generate the docs tables from it. Add a CI check that diffs `var(--mini-…)` usages in src against the manifest. Fix or remove every phantom token.

### [high] theming-9: Series colors only partly themable: only 5 consumers, independent cycling, raw palette hex in events and gradients (theming)
- Evidence: Consumers: pie:213, half-pie:208, stacked-area:256, stream:253, radial-bar:297,358. Palette cycles at 16 (palette.js:28-30) while tokens are `--mini-chart-color-${index+1}` with no modulo. Radial gradient uses raw hex: radial-bar:298,359, :196. Events report palette hex: pie:130, half-pie:128, radial-bar:158, stacked-area:156, stream:155. Host `--mini-chart-segment-color` is always overwritten inline (pie:213, half-pie:208); `--mini-chart-fill` is overridden by local rules (bar:81-86, pie:98-99, combo:118-119, win-loss:102-104, ohlc:98-101). Demo claim 'wraps around automatically if > 8': demo/index.html:2655
- Detail: A theme that defines 8 series colors (as the docs and demo suggest) shows series 9–16 in the built-in palette. Radial gradients and hover `detail.color` ignore user tokens, so tooltips and legends show the wrong colors. Combo has no series tokens despite its docs. Radial tracks and gauge zones have no per-index parts.
- Rec: Introduce `--mini-chart-series-1..12` plus a JS-side cycle length (default 12, overridable via a `series-count` attribute or a theme). Every series element gets `part="series series-N …"` and a private `--_series` inline var. Resolve event colors with getComputedStyle(el).fill/stroke. Gradient defaults derive from series tokens. Remove `--mini-chart-fill` and `--mini-chart-segment-color` as public API.

### [high] theming-10: Win-loss `win-color` / `loss-color` / `tie-color` attributes do nothing (api)
- Evidence: Observed at src/components/mini-win-loss-chart.js:24-26 but never read (only CSS tokens at :102-104); documented in docs/components/mini-win-loss-chart.md:19-21; typed in src/react/index.ts:173-178 and src/angular/mini-chart.directive.ts:675-698
- Detail: The attributes are a documented, typed styling API in three frameworks, and they have no effect.
- Rec: Remove the attributes in favor of tokens, or map them to private inline vars inside the shadow root (`--_win: <attr>`) with precedence attribute > token > default. Decide on one global rule for color attributes versus tokens.

### [high] theming-11: ::part names inconsistent, missing state parts, and 12+ documented parts that don't exist (api)
- Evidence: `track` = gauge zone arc (gauge:352,369), progress background (progress:143), radial group `<g>` (radial-bar:265); `bar` = stroked tick path in OHLC (ohlc:209); `group` = clip group (line:145, area:173) vs mask group (pie:85, half-pie:83); candlestick/OHLC expose state only via `data-bullish` (candlestick:266-270, ohlc:220-224), which ::part cannot select; `point point-point` (line:338,365; area:443,469). Docs: slice (pie.md:25, half-pie.md:24), mask-line (line.md:24), layer (combo.md:43), tick/open/close/bullish/bearish (ohlc.md:27-32), bullish/bearish (candlestick.md:30-31), zone (gauge.md:42), circle/trendline (scatter.md:36-37), range-marker (range-bar.md:36), range-0 (bullet.md:32); `:nth-child` advice with ::part (pie.md:25, stacked.md:28) is invalid
- Detail: Part names are public API and must be stable before 2.0. Users cannot style bullish or bearish candles via ::part, cannot target radial rings or gauge zones by index, and the docs send them to names that don't exist.
- Rec: Define a shared part vocabulary (marks: line, area, bar, point, segment, arc, track, band, marker, needle, label; modifiers: positive, negative, neutral, series-N, first, last, min, max, active; guides: reference-line, crosshair, baseline, trend-line). Add the new names alongside the old ones (the part attribute accepts lists) throughout v1.x, document per component from the manifest, and drop the old names in 2.0.

### [high] theming-12: No dark mode, presets, or token layer; the demo redefines 28 tokens twice (theming)
- Evidence: No prefers-color-scheme, color-scheme or light-dark() anywhere in src (grep); demo/index.html:73-101 (dark) and :122-150 (light) redefine the full set; white halos assume a light background: line:118, area:124 (`stroke: white`), range-bar:111 (`#ffffff`), scatter:111; package.json exports ships no CSS; README:35 claims 'Adaptive Dark & Light Theming'
- Detail: Defaults rely on mid-grey rgba(128,128,128,a) and hard-coded white, so charts look acceptable only on light backgrounds, and every consumer has to rebuild a dark theme by hand. There is no shipped preset, theme object or apply helper. The demo implements presets in JS and pushes them as inline styles (app.js:970-1049).
- Rec: Ship tiered tokens with AA-checked defaults, use `light-dark()` (with a `@media (prefers-color-scheme)` fallback) inside the private token block, and add a `--mini-chart-surface` token for halos. Ship optional `themes/light.css`, `dark.css`, `auto.css`, `high-contrast.css` and `okabe-ito.css` via package exports.

### [high] theming-13: Gradients are attribute-only, parsed 5 times with an ad hoc grammar, and disconnected from tokens (duplication)
- Evidence: Parsers: area:385-395, bullet:193-208, gauge:243-259, progress:205-220, radial-bar:191-211 (`replace(/'/g,'"')` + comma split). Hard-coded defaults: bullet:197, gauge:248 (ignores safe/warn/danger), progress:209, radial-bar:196. Inconsistent stop-opacity: area:406 (.55/.05) vs :414/:419 (.45/.02). Per-instance random ids: area:128, bullet:139, gauge:158, progress:132, radial-bar:255. Not mentioned in any docs/components/*.md. Demo sets the attribute element by element: demo/app.js:1230-1234
- Detail: A CSS theme cannot change gradients. Values like `rgb(16,185,129), rgb(239,68,68)` are split into 6 invalid stops. Gauge gradient mode reverts to Tailwind hex even when a theme redefines safe/warn/danger. Direction, opacity and stop count are not configurable, and each chart behaves differently.
- Rec: Write one `core/gradient.js` (parse, normalize, render stops) with a strict grammar: boolean or a JSON array of colors or of {offset, color}. Default stops are `var(--mini-chart-gradient-1..n)` tokens derived from the accent or series. Set stop-color through the style property so var() works. Deterministic per-instance ids. Document the grammar once.

### [medium] theming-14: var() inside SVG presentation attributes (gauge zones, area flat fill) (theming)
- Evidence: src/components/mini-gauge-chart.js:22-24 (zone colors as `var(...)` strings) written to the `stroke` attribute at :368-372; src/components/mini-area-chart.js:382 `setAttribute('fill','var(--mini-chart-fill, currentColor)')`; user `zones` colors and gradient stops also go into attributes (gauge:342-345, area:403-406)
- Detail: The color theming depends on var() substitution inside presentation attributes, which falls outside the plain presentation-attribute grammar and is engine-dependent. Presentation attributes also have the lowest precedence and the least predictable behavior. The `zone-change` event detail returns the unresolved `var(...)` string as zoneColor (gauge:390).
- Rec: Set themable paint with element.style or CSS custom properties (`style.setProperty('--_zone', color)` + `stroke: var(--_zone)`). Resolve colors with getComputedStyle before putting them in event detail.

### [medium] theming-15: Styling attributes baked into the stylesheet once; changes ignored and precedence inverted (bug)
