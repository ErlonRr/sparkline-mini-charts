# adapters

## Summary
I read the three adapters in full: React (src/react/index.ts, 327 lines), Vue (src/vue/index.ts, 115 lines) and Angular (src/angular/mini-chart.directive.ts, 860 lines). I checked them against the 17 components and against the actual framework runtimes installed in a sibling project on disk: react-dom 18.3.1, @vue/runtime-dom and runtime-core 3.5.41, svelte 5.56.8, and @angular/core plus compiler-cli 20.3. I also probed `el.data = ...` on all 17 element prototypes in memory, without writing anything to disk. Most of the adapter layer does not work today.

The root cause sits in the core data contract. The base `data` setter JSON-stringifies whatever it receives (src/core/mini-chart-element.js:48-51). Nine of the 17 components override `get data()` without a setter. Any framework that assigns `el.data` therefore either double-encodes the JSON string the React and Vue wrappers pre-serialize, which renders an empty chart, or throws a TypeError. That covers React 19, Vue 3, Svelte 5, Preact, Solid and the Angular directives.

The Angular adapter is built by Vite rather than the Angular compiler. Its classes carry no Ivy metadata, so an AOT app cannot import them at all (NG2012). Separately, the `MiniChartDirective` that every doc recommends never registers the custom elements. The React wrapper turns `style` into a JSON string, which makes React throw. It also turns `className` into a `class-name` attribute and throws away its typed event callbacks. The Vue wrapper declares only 3 props, so object options such as zones and ranges are coerced with String() and silently ignored, and nothing is typed.

Three options default to true when the attribute is absent (round-caps, hollow-bullish, shared-domain), so React and Angular cannot turn them off. Event names have drifted: `slice-select` is declared everywhere but never dispatched, and `sparkline-select` and `progress-complete` cannot be reached through any adapter. Elements expose no properties besides `data`, so frameworks that set properties (Solid, Lit `.prop`, Angular `[x]`) silently lose every option. There are no typings for the raw elements and no custom-elements.json. Svelte support exists only as a README claim, and the documented Svelte snippet is itself broken.

Per-chart metadata is copied by hand into at least 5 places; one tag name appears in 14 files, and the Angular file has 135 input()/effect() pairs. The only adapter test checks `typeof` against a dist/ that CI has not built yet, and it fails locally (not ok 12, ERR_MODULE_NOT_FOUND). The fix order is:
1. Repair the core property contract (data setter, property accessors, upgrade pattern, boolean semantics, event table).
2. Introduce one chart metadata manifest.
3. Generate thin React/Vue/Angular wrappers plus typings for every framework and the custom-elements.json from it.
4. Compile Angular with ng-packagr.
5. Add real behavioral, type and SSR tests for each framework, with build running before test in CI.

## Proposals
- PREREQUISITE: fix the core property contract before any adapter work, since every adapter depends on it. (1) MiniChartElement owns the only `data` accessor pair. The setter accepts `unknown`: a string is parsed as JSON; an array or object goes through `static normalizeData(raw): T`, overridden per chart, and is stored privately without reflecting to the attribute; then requestRender(). (2) Reflected, typed property accessors for every attribute (camelCase property ↔ kebab attribute; number, boolean, enum and json coercion; reflect primitives only), generated from metadata so `observedAttributes` cannot drift. (3) The lazy upgrade-property pattern in connectedCallback. (4) Standard HTML boolean semantics: no attribute defaults to true, so round-caps, hollow-bullish and shared-domain are renamed with deprecated aliases. (5) A typed event table with exported detail types; slice-select is either implemented or removed, and sparkline-select and progress-complete are formalized. Once this lands, React 19, Vue, Svelte, Preact, Solid and Lit work with the raw elements and only need typings.
- SINGLE SOURCE OF TRUTH: add one metadata module per chart, e.g. `src/charts/line/line.meta.js`, exported as `defineChartMeta({ tag: 'mini-line-chart', className: 'MiniLineChart', summary, data: { tsType: 'number[]', example: [10,20,14] }, attributes: { curve: { type: 'enum', values: ['linear','smooth','step'], default: 'linear' }, min: { type: 'number' }, referenceValue: { attr: 'reference-value', type: 'number' }, trendColor: { attr: 'trend-color', type: 'enum', values: ['auto','none'] }, interactive: { type: 'boolean' } }, events: { 'sparkline-hover': { detail: '{ index: number; value: number; x: number; y: number }' }, 'sparkline-leave': {} }, cssProperties: [...], parts: [...] })`. The runtime consumes it to derive observedAttributes, property accessors and coercion, which also replaces the 17 ad-hoc gradient and boolean parsers. A codegen script consumes the same data. Option A (recommended): metadata as code, with custom-elements.json emitted as a generated artifact; one truth for both runtime and codegen, at the cost of about 1-2 KB of runtime schema. Option B: JSDoc tags plus @custom-elements-manifest/analyzer as the source, generating wrappers from custom-elements.json; this is standard tooling, but the CEM cannot express data normalizers or runtime coercion, so runtime and docs can still drift. A pragmatic hybrid is A, plus emitting JSDoc and CEM so the ecosystem tools (Storybook, lit-analyzer, VS Code, JetBrains) work.
- CODEGEN OUTPUTS (`pnpm codegen`, with a CI drift check of `pnpm codegen && git diff --exit-code`): React wrappers and Props/Ref/EventMap types; Vue components with typed props and emits plus a `GlobalComponents` augmentation; Angular directive sources, compiled later by ng-packagr; `HTMLElementTagNameMap` and per-element event-map augmentations; JSX `IntrinsicElements` augmentations for react (React 19 direct use), preact, solid-js and svelte/elements; custom-elements.json, vscode.html-custom-data.json and web-types.json; docs/components/*.md attribute, event and CSS tables; demo framework snippets; vite.config entries and package.json `exports`; compile-checked example files (tsx, vue, angular, svelte) that serve as type tests.
- FRAMEWORK TIERING. Tier 1, thin generated wrappers. React: a `createComponent` pattern in the style of @lit/react, which renders the tag, passes through standard React props untouched (className, style, aria-*, data-*), sets chart props as element properties in useLayoutEffect, attaches events with addEventListener from `onSparklineHover`-style props, types refs to the element class, ships `'use client'` and per-chart subpaths, and supports React `^18.3 || ^19`. Vue: typed `defineComponent` per chart with props passed as DOM properties, typed emits, `inheritAttrs: false`, plus an exported `isSparklineElement` helper for `compilerOptions.isCustomElement` and an optional Nuxt module/plugin for client registration. Angular: generated standalone directives using `host` property, attribute and listener bindings (no effects), camelCase signal inputs with union types, `provideSparklineCharts()` for registration, no catch-all directive, built by ng-packagr against Angular 20. Tier 2, typings and docs only: Svelte 5 (svelte/elements augmentation, `onsparkline-hover`), Solid (JSX augmentation; docs on `prop:`, `attr:` and `on:`), Preact, Lit, vanilla TS. Tier 3, docs and recipes only: Astro (client `<script>` registration, attribute API), Qwik.
- PACKAGE LAYOUT, with tradeoffs. (a) Status quo, a single package with subpath exports: simplest install, but ng-packagr output cannot live comfortably inside a Vite build, the manifest carries three optional peers, and every adapter shares one release cadence and one test setup. (b) Hybrid, for v1.x: keep `sparkline-mini-charts` (core plus React and Vue subpaths, plain TS builds) and publish `@sparkline-mini-charts/angular` built with ng-packagr; this has the least disruption and fixes the Angular blocker quickly. (c) Recommended for v2: a pnpm-workspace monorepo with lockstep versions via a changesets `fixed` group. It would hold `packages/core` (`sparkline-mini-charts`: zero dependencies, elements, define/register, math, all Tier 2 typings, custom-elements.json, web-types) plus `packages/react`, `packages/vue` and `packages/angular` (ng-packagr), each with precise peers and its own test runner. It would also hold `tools/codegen` (private), `apps/demo`, and `apps/fixtures` (next-app-router, nuxt, angular-ssr, sveltekit, astro). This costs more release plumbing in exchange for clean peer ranges, a framework-native build per adapter, and isolated, independently testable adapters. Migration: v2 drops the `sparkline-mini-charts/react|vue|angular` subpaths, with a codemod or migration doc; v1.x keeps them working.
- TEST AND CI STRATEGY. Build before test. Run a unit contract test over all 17 classes: data setter round-trip for string, array and object; properties ↔ attributes; boolean semantics; the upgrade-property pattern; the event table matching dispatchEvent calls (a static grep test). Run the React test suite on 18.3 and 19.x via @testing-library/react with happy-dom (data, style, className, events, refs, SSR renderToString, hydration). Vue: @vue/test-utils plus @vue/server-renderer and a hydration test. Angular: a TestBed suite against the ng-packagr output plus an `ng build` fixture with strictTemplates. Svelte 5: a compile-and-mount test. Type tests: expect-type/tsd for React, vue-tsc for Vue, ngc for Angular, svelte-check for Svelte. Add SSR smoke fixtures for Next App Router, Nuxt, Angular SSR, SvelteKit and Astro, and a size-limit budget per entry.
- PHASED BACKLOG. v1.4.1 hotfix, non-breaking: (A1) base data setter accepting string|array, with the 9 getter overrides replaced by a normalize hook; (A2) React stops stringifying data, whitelists chart attributes, passes style and className untouched, and wires onSparklineHover/Leave/ZoneChange via ref listeners; (A3) Vue passes data and object options as properties; (A4) Angular catch-all calls defineMiniCharts and README marks the Angular adapter experimental; (A5) fix the Svelte and demo snippets; (A6) CI runs build before test. v1.5, additive: (B1) metadata manifest plus generated property accessors, upgrade pattern and observedAttributes; (B2) boolean attribute renames with deprecated aliases; (B3) typed event table with slice-select resolved and sparkline-select and progress-complete exposed; (B4) raw-element typings, custom-elements.json, web-types and VS Code data; (B5) `@sparkline-mini-charts/angular` via ng-packagr with host bindings; (B6) per-chart adapter subpaths, `'use client'`, sideEffects cleanup; (B7) bounded peer ranges and adapter CJS dropped; (B8) the adapter test matrix. v2.0, breaking: (C1) monorepo split with generated React, Vue and Angular wrappers; (C2) remove `MiniChartProps` with `any`, the kebab prop aliases, the catch-all directive and the deprecated boolean attributes; (C3) optional configurable tag prefix and scoped registry support.

## Findings

### [critical] adapters-1: Adapters pre-serialize `data` to a JSON string that React 19, Vue 3 and Svelte 5 assign through the `data` property → double-encoded, empty charts (bug)
- Evidence: src/react/index.ts:233 `data: typeof data === "string" ? data : JSON.stringify(data)`; src/vue/index.ts:48 (same); src/core/mini-chart-element.js:48-51 `set data(values){ this.setAttribute("data", JSON.stringify(values)) }`; @vue/runtime-dom 3.5.41 shouldSetAsProp `return key in el` (L858); @vue/runtime-core hydration re-patches CE props (L2207-2212); svelte 5.56.8 src/internal/client/dom/elements/attributes.js:588-615; docs/getting-started.md:146 and demo/index.html:3328-3330 `data={JSON.stringify(revenue)}`; probe: line chart `el.data="[1,2,3]"` → attribute `"\"[1,2,3]\""` → getter `[]`
- Detail: `data` is defined as an accessor on MiniChartElement.prototype, so `'data' in el` is true for every chart. React 19, Vue 3.5 and Svelte 5 therefore assign the wrapper's JSON string through the setter. The setter stringifies it a second time, `parseNumericData` gets a JSON string instead of an array and returns []. With Vue, the README example (README.md:199-211) renders the 'Empty chart' state for all 17 charts, including after Nuxt hydration. With React 19, the devDependency version, the 8 base-setter charts render empty. The documented Svelte snippet fails the same way. Only React 18, which always uses attributes, works by accident.
- Rec: Adapters must never pre-serialize: pass arrays and objects as properties. In the core, make the base setter accept `unknown`: a string is parsed as JSON source; anything else is normalized and stored in a private field, then a render is requested. Do not reflect large data back into the attribute. Add a regression test that assigns string, array and object data to all 17 classes.

### [critical] adapters-2: 9 of 17 components shadow the base `data` setter with a getter-only accessor → any property assignment throws TypeError (bug)
- Evidence: get data() without set in src/components/mini-ohlc-chart.js:61, mini-bullet-chart.js:69, mini-candlestick-chart.js:69, mini-combo-chart.js:79, mini-radial-bar-chart.js:78, mini-range-bar-chart.js:68, mini-scatter-chart.js:70, mini-stacked-area-chart.js:74, mini-stream-chart.js:73 (grep 'set data' = 0 in each); src/angular/mini-chart.directive.ts:104 `if (d !== undefined) el.data = d;` (repeated for every directive); probe: 'THROWS TypeError: Cannot set property data of #<MiniOhlcChart> which has only a getter'
- Detail: A subclass accessor with only a getter hides the inherited setter, so assignment throws in strict-mode code. The Angular directives throw inside effects for bullet, candlestick, combo, ohlc, radial-bar, range-bar, scatter, stacked-area and stream. React 19 throws during commit and unmounts the tree. Svelte 5 and Lit `.data=` throw. Vue catches the error and warns, leaving an empty chart. Preact catches it and falls back to `setAttribute('data', '1,2,3')`, also empty. Vanilla `el.data = [...]` is broken for these 9 charts too.
- Rec: Define the `data` getter/setter pair only in MiniChartElement. Subclasses override a hook such as `static normalizeData(raw: unknown): T` (or `parseData`). Add a test that iterates all 17 classes, asserting that no subclass prototype owns a `data` descriptor and that `el.data = sample` round-trips.

### [critical] adapters-3: Angular adapter is compiled by Vite, not the Angular compiler → unusable in AOT apps; signal inputs/outputs invisible even under JIT (packaging)
- Evidence: vite.config.js:34 (`angular: fromRoot("src/angular.ts")` in Vite lib build), vite.config.js:48-54 (vite-plugin-dts → plain .d.ts without `static ɵdir/ɵfac`); tsconfig.json:7 experimentalDecorators; package.json:177-186 (no ng-packagr / @angular/compiler-cli); src/angular/mini-chart.directive.ts:78-81 raw `@Directive`; Angular compiler-cli 20.3 chunk-YDQJH54W.js:7996 'Component imports must be standalone components, directives, pipes, or must be NgModules.'; @angular/core debug_node.mjs:197 "needs to be compiled using the JIT compiler, but '@angular/compiler' is not available"
- Detail: An AOT consumer writing `imports: [MiniLineChartDirective]` gets a compile error, because the .d.ts has no `ɵɵDirectiveDeclaration`. At runtime the legacy decorator defines a lazy `ɵdir` that needs the JIT compiler facade, so it errors unless @angular/compiler is loaded. Even under JIT, `input()`/`output()` fields are discovered only through the Angular CLI's JIT transform, which runs on application sources and not on node_modules. As a result `[data]` would bind to the native property and `(sparklineHover)` would never fire. The existing test (test/components.test.js:404-410) only checks `typeof`.
- Rec: Build the Angular adapter with ng-packagr (Angular Package Format, partial compilation), as its own workspace package or secondary entry, compiled against the lowest supported Angular (20.x). Add a CI fixture that runs `ng build` on a tiny app with strictTemplates, importing every directive.

### [critical] adapters-4: React wrapper mangles standard React props: `style` is JSON-stringified (React throws), `className`→`class-name`, `tabIndex`→`tab-index` (bug)
- Evidence: src/react/index.ts:242-264 loops over all remaining props: `typeof val === "object"` → `JSON.stringify(val)` (L255-257); kebab regex `/([a-z0-9])([A-Z])/g` applied to every key (L256,259,262); src/react/index.ts:40 BaseSparklineProps extends HTMLAttributes (advertises style/className); react-dom 18.3.1 development.js:2961-2963 throws 'The `style` prop expects a mapping from style properties to values, not a string'
- Detail: `<MiniLineChart style={{ width: 120 }} />` crashes render. So does `style={{ '--mini-chart-color': 'red' }}`, which is the library's own theming mechanism (README.md:128-156). `className="h-8"` renders `class-name="h-8"`, so no class is applied. `tabIndex`, `contentEditable` and `suppressHydrationWarning` become bogus kebab attributes. `dangerouslySetInnerHTML` and element `children` get stringified, which throws or produces circular JSON.
- Rec: Transform only keys that are known chart attributes for that chart, taken from generated metadata. Pass every other prop to React untouched. Add a test that passes style, className, aria-* and data-* props.

### [high] adapters-5: React event callbacks are silently dropped; the raw kebab passthrough cannot work in React 18 or 19 (bug)
- Evidence: src/react/index.ts:32-37 typed SparklineEventHandlers; L224-227 `onSparklineHover, onSparklineLeave, onSliceSelect, onZoneChange` destructured and never used; L245-248 raw `onSparkline-hover` passthrough; react-dom 18.3.1 development.js:394-399 (function values on custom elements removed); CHANGELOG.md:13 and README.md:244 claim 'event listener bindings (onSparklineHover, onZoneChange…)'; demo/index.html:3220 falls back to `onPointerEnter`
- Detail: The documented, typed callbacks never fire. React 18 never attaches custom-event listeners from props. React 19 calls `addEventListener(name.slice(2))` case-sensitively, so `onSparkline-hover` listens for 'Sparkline-hover', which is never dispatched. Only the undocumented, untyped `onsparkline-hover` would work, and only on React 19. `sparkline-select` and `progress-complete` cannot be received at all.
- Rec: Attach listeners in useLayoutEffect through an internal ref merged with the forwarded ref; this works on React 18 and 19. Drive it from a generated event table (`onSparklineHover` → `sparkline-hover`) and type each callback as `(e: CustomEvent<Detail>) => void`.

### [high] adapters-6: Documented Angular `MiniChartDirective` never registers the elements, claims only 8 inputs, and duplicates outputs when combined with per-chart directives (bug)
- Evidence: src/angular/mini-chart.directive.ts:821-860 (no defineMiniChart; inputs only data,label,curve,points,min,max,gradient,interactive); recommended in README.md:168-185, docs/getting-started.md:116-135, demo/app.js:604 and :715; SPARKLINE_DIRECTIVES L798-816; Angular TCB chunk-YDQJH54W.js:15305 `const checkElement = directives.length === 0` (unclaimed inputs still schema-checked)
- Detail: Following the README leaves the custom elements undefined, so nothing renders. Meanwhile `el.data = d` writes an own property onto the un-upgraded element, which would shadow the accessor even if `register` were imported later. `[zones]`, `[ranges]` and `[gap]` are unclaimed, so they fail with NG8002 unless CUSTOM_ELEMENTS_SCHEMA is used, and then they bind a dead expando. Importing the catch-all together with SPARKLINE_DIRECTIVES makes two directives match one element: effects run twice and `(sparklineHover)` handlers fire twice.
- Rec: Remove the catch-all, or generate it so it registers all charts and claims all inputs. Document the per-chart directives and offer `provideSparklineCharts()` / `SPARKLINE_DIRECTIVES` as the official path.

### [high] adapters-7: Default-true boolean attributes cannot be turned off through the adapters; boolean semantics differ by chart and by framework (api)
- Evidence: mini-radial-bar-chart.js:112 `getAttribute("round-caps") !== "false"`; mini-candlestick-chart.js:102 (hollow-bullish); mini-combo-chart.js:264 (shared-domain); React drops false booleans src/react/index.ts:258-260; Angular inputs default false and remove the attribute: mini-chart.directive.ts:375, 506, 590 + syncAttr L34-40; mini-stacked-area-chart.js:233 `hasAttribute("normalize")` while Vue 3 renders `:normalize="false"` as `normalize="false"`; mini-area-chart.js:380-382 (absent gradient = ON) vs React omitting `gradient={false}` and Angular sending "false" (syncJsonAttr L43-51)
- Detail: `roundCaps={false}`, `hollowBullish={false}` and `sharedDomain={false}` have no effect in React or Angular. The Angular input defaults (false) contradict the component defaults (true). In Vue, `:normalize="false"` turns normalization on. `gradient={false}` disables the area gradient in Angular but not in React. The same input means different things depending on the adapter.
- Rec: Use standard HTML boolean semantics everywhere: presence means true, absence means false, and nothing defaults to true. Rename or replace the three options (`flat-caps`, `solid-bullish`, `independent-domain`, or enumerated attributes such as `caps="round|flat"`), keeping deprecated aliases for one minor. Share one boolean parser in the core, and have adapters set typed properties instead of attributes.

### [high] adapters-8: Elements expose no JS properties except `data` → property-first frameworks silently ignore every option (api)
- Evidence: grep across src/: the only accessors are `get data`/`set data` (src/core/mini-chart-element.js:43-51 plus 9 getter overrides); options read with getAttribute only (e.g. mini-gauge-chart.js:172, 244, 267; mini-line-chart.js:19-29 attribute list); no property for curve/min/max/gradient/etc.
- Detail: Solid assigns custom-element props as properties by default (kebab→camel), so `curve="smooth"` creates an expando and nothing changes. Angular `[curve]="x"` under CUSTOM_ELEMENTS_SCHEMA and Lit `.curve=${x}` behave the same. In Vue, camelCase fall-through attrs such as `referenceValue="5"` become `setAttribute('referenceValue')`, which HTML lowercases to `referencevalue`, so the value is ignored. In vanilla JS, `el.min = 0` does nothing. This blocks typed property-based wrappers for every framework.
- Rec: Generate reflected, typed property accessors from chart metadata for every attribute: camelCase property ↔ kebab attribute, coercion for number, boolean, enum and JSON, reflecting primitives only. Combine this with the upgrade-property pattern.

### [high] adapters-9: Vue wrapper declares only data/label/interactive: chart options fall through untyped and objects are coerced with String() (api)
- Evidence: src/vue/index.ts:27-40 (3 props), L29 `PropType<any>`, L41 untyped emits array, L47 `...attrs`; mini-gauge-chart.js:267-276 (zones parsed only as JSON); mini-bullet-chart.js:226 (ranges); mini-gauge-chart.js:254-256 (gradient comma-split fallback)
- Detail: `:zones="[{upTo:50,color:'green'}]"` becomes `zones="[object Object]"`; JSON.parse fails and default zones are used silently. The same happens to `:ranges`. `:gradient="['#f00','#0f0']"` works only by luck, through the comma-split fallback. Volar offers no autocompletion or validation for curve, min, needle-type and the rest. Event payloads are untyped, and every chart declares `slice-select`/`zone-change` emits even when it never dispatches them.
- Rec: Generate one `defineComponent` per chart with typed props (`PropType<T>`, enum validators) and typed `emits`. Pass options as DOM properties (or the `.prop` modifier) instead of attributes. Set `inheritAttrs: false` and spread `attrs` deliberately.

### [high] adapters-10: Event names have drifted: `slice-select` is declared but never dispatched, while `sparkline-select` and `progress-complete` are unreachable through any adapter (api)
- Evidence: dispatchEvent grep: sparkline-hover/leave in all 17; zone-change mini-gauge-chart.js:384; sparkline-select mini-candlestick-chart.js:172; progress-complete mini-progress-chart.js:303; `slice-select` dispatched nowhere but declared in src/react/index.ts:35, src/vue/index.ts:41, src/angular/mini-chart.directive.ts:302, 342, 839; all events typed bare `CustomEvent` (react L33-36, directive L56-59)
- Detail: The Angular pie and half-pie `sliceSelect` outputs can never emit. The candlestick click event and the progress completion event have no React prop, Vue emit or Angular output. Event detail shapes (index, value, x, y, OHLC fields, zoneIndex…) are undocumented and untyped, and no events appear in docs/components.
- Rec: Put an `events` table with detail types in the chart metadata. Generate `MiniXxxChartEventMap` types and adapter bindings from it. Either implement `slice-select` in pie and half-pie or remove it. Consider a consistent prefix such as `mini-chart-*`, with deprecated aliases.

### [high] adapters-11: No typings for the raw custom elements and no Custom Elements Manifest (typing)
- Evidence: grep 'HTMLElementTagNameMap|IntrinsicElements|GlobalComponents|SvelteHTMLElements|custom-elements.json|web-types' over src/, package.json, docs/, README.md → no matches; no @attr/@prop/@fires/@cssprop/@csspart JSDoc in components (e.g. src/components/mini-line-chart.js:13-29); package.json has no `customElements` field
- Detail: `document.querySelector('mini-line-chart')` is typed as Element. React 19 JSX `<mini-line-chart>` is a TS error. Vue templates need `isCustomElement` and get no types, and Svelte, Solid and Preact users get nothing. VS Code and JetBrains offer no completion, and Storybook cannot auto-generate controls. This is the backbone of 'multi-framework' support, and it is missing entirely.
- Rec: Generate from metadata: custom-elements.json (plus a `customElements` field in package.json), a `HTMLElementTagNameMap` and `HTMLElementEventMap` augmentation, and JSX augmentations for react, preact, solid-js, svelte/elements and Vue `GlobalComponents`. Also generate vscode.html-custom-data.json and web-types.json.

- Rec: After the core data fix, document `data={revenue}`. Ship a `svelte/elements` augmentation, add a Svelte 5 compile-and-mount test, and remove the 'bindings' wording unless typings ship.

Add type tests (expect-type/tsd, vue-tsc, ngc strictTemplates, svelte-check) and SSR fixture apps.

### [medium] adapters-14: React entry has no 'use client' and registers on import → charts never upgrade when imported from a Server Component (ssr)
- Evidence: src/react/index.ts:1 (no directive), L217 `defineMiniChart(tagName, component)` at module evaluation; vite.config.js:9-55 (no banner or directive preservation); README.md:190 and docs/getting-started.md:78 put "use client" in user code
