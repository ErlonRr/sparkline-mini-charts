# components-bars-financial

## Summary
The six bar-family and financial components (bar, win-loss, range-bar, bullet, candlestick, OHLC; 1,783 LOC in total) all skip the base class's render()/renderChart() contract. Each one has its own copy of the same lifecycle: a #initialized flag, a #createDOM step that runs once, an incremental #updateChart, setTimeout-based removal of inline transitions, and listener setup and teardown. That code is duplicated almost line for line six times. I confirmed four bugs with inline fake-DOM probes against the real source: (1) bullet, range-bar, candlestick and OHLC override `get data()` without a setter, so `el.data = ...` throws a TypeError. The Angular directives always assign `el.data`, so Angular integration is broken for all four, and the JS-property API promised in the README does not exist for them. (2) A `null` entry in data crashes render: `data="[[1,2],null]"` on range-bar and `data="null"` on bullet both throw. (3) All six permanently lose their hover/click listeners after a disconnect followed by a reconnect. (4) Several attributes are read only on the first render (win-loss/range-bar `radius`, candlestick `hollow-bullish`/`wick-width`, OHLC `tick-width`), so changing them later does nothing. Some attributes are documented, typed in the wrappers and observed, but never implemented: win-loss `win-color`/`loss-color`/`tie-color` and bar `baseline`. Win-loss `mode` has three different vocabularies (code: status, docs: binary, React type: uptime). Structured data is weakly validated. Range-bar accepts any JSON. Bullet treats a valid JSON scalar (`data="75"`) as 0. Candlestick/OHLC accept extra columns but feed them into the scale domain, so OHLCV volume flattens the chart, and object rows are not supported. The range-bar object form in the docs (`{min,max,value}`) does not match the code (`current`), so the marker silently disappears. Theming is the weakest area. The same concept has four different names for positive/negative colors. `--mini-chart-range-color` and `--mini-chart-danger-color` mean different things in different components. Bullet reads a non-namespaced global `--primary`. Default accent colors differ between charts (#2563eb, #3b82f6, #10b981, while the README says #0ea5e9). The `--mini-chart-color-1..8` tokens advertised in the README, docs and demo are consumed nowhere. Bullet's measure bar turns black when `gradient="false"`, which is exactly what the Angular and Vue wrappers emit. The docs drift heavily: candlestick and OHLC document parts that do not exist, bullet documents CSS variables that do not exist, and the bar doc still contains draft text. Event detail shapes differ in every component, and `sparkline-select` (candlestick) is not exposed by any wrapper. Tests only count parts after the first render, and the framework test depends on a built `dist/`, so it fails on a clean checkout (11 pass, 1 fail).

## Proposals
- Typed attribute and property schema in the base class: `static props = { gap: number({ default: 0.2, min: 0, max: 0.8 }), radius: number({ default: 2 }), mode: enumOf(['win-loss','status']), hollow: boolean(), ... }`. From it, generate observedAttributes, reflecting getter/setter pairs (removing the getter-only `data` bug for good), parsing and clamping, dev-mode warnings, and a `changed` set passed to update(). The same schema feeds a Custom Elements Manifest, from which React, Vue and Angular wrapper types and the docs tables are generated, eliminating mismatches like `mode` and `win-color`.
- Data normalization layer in src/core/data.js with one normalizer per chart family: `normalizeSeries` (number|null; gaps kept with their original index), `normalizeOutcomes` (win-loss: -1/0/1 plus booleans and strings such as 'W'/'L'), `normalizeRanges` ([lo,hi,cur?] or {min|low, max|high, value|current}), `normalizeBullet` (number | [v,t,...ranges] | {value,target,ranges,min,max}), and `normalizeOhlc` (tuple formats selected by a `format` attribute: ohlc/tohlc/ohlcv, plus {open,high,low,close,time?,volume?}, with high/low repair). Each returns `{ items, domainHint, issues }`. The `data` property stores objects directly (no stringify round-trip) and accepts strings as-is.
- Incremental render core: replace the six copies with a base `IncrementalChartElement` offering `createDOM()` (static nodes, listeners attached once), `update(model, changed)`, a shared keyed `MarkPool` (create, update and trim SVG nodes), a shared `animateEntrance(nodes, { totalStagger: 300 })` that honors reduced motion and caps the total delay, and a validated domain/clamp helper. The financial charts share one `FinancialChartBase` (parser, layout, events), with candlestick and OHLC differing only in mark rendering.
- Theming token specification (v2): semantic namespaced tokens (`--mini-chart-accent`, `--mini-chart-positive`, `--mini-chart-negative`, `--mini-chart-neutral`, `--mini-chart-track`, `--mini-chart-band-1..3`, `--mini-chart-palette-1..8`, `--mini-chart-radius`, `--mini-chart-stroke-width`, `--mini-chart-mark-opacity-inactive`, `--mini-chart-gradient-1..3`). Every component token falls back to a semantic token, with legacy names (bullish/bearish, win/loss, positive/negative, range-color) kept as deprecated aliases for one major version. Remove `--primary`. Expose direction and state as part tokens (`candle bullish`, `bar negative`, `range-bar clipped`). Use one shared constructable stylesheet per class. Ship a light/dark preset CSS file plus a token reference page generated from source.
- Unified interaction and a11y contract: events `mini-chart-hover`, `mini-chart-leave` and `mini-chart-select`, with typed `detail: { chartType, index, datum, raw, anchor: DOMRect }` and no internal nodes. Keyboard roving focus over marks (arrows, Enter, Escape) produces the same events. Generate the typed event bindings for React (onMiniChartHover…), Vue emits and Angular outputs from the manifest.
- Test strategy for stability: a real-browser component test suite (@web/test-runner or Vitest browser mode) with a shared edge-case matrix applied to all 17 elements (empty, single, null, NaN, numeric strings, negatives, all-equal, min>max, out-of-domain, 10k points, attribute removal, property assignment, disconnect/reconnect, event payload snapshots). Add docs-vs-manifest drift checks in CI, and run wrapper smoke tests against src, not dist.

## Findings

### [critical] components-bars-financial-1: Getter-only `data` override removes the setter: `el.data = …` throws in bullet, range-bar, candlestick and OHLC (Angular wrappers broken) (bug)
- Evidence: src/components/mini-bullet-chart.js:69 `get data() {` (no setter); mini-range-bar-chart.js:68; mini-candlestick-chart.js:69; mini-ohlc-chart.js:61; the base defines both accessors at src/core/mini-chart-element.js:44-51. Angular: src/angular/mini-chart.directive.ts:520-523, 562-565, 643-646, 730-733 `if (d !== undefined) el.data = d;`. README.md:37 promises 'Synchronized ... JavaScript properties'. Probe: `Cannot set property data of #<MiniBulletChart> which has only a getter` (same for the other three).
- Detail: In JS, a subclass that defines only `get data()` creates an accessor on its prototype whose setter is undefined. That accessor shadows the base class setter. In strict-mode code (ES modules, Angular/TS output, React DOM), the assignment throws a TypeError. Every Angular directive for these four charts assigns `el.data` inside an effect, so the chart never receives data and an error is logged. Vanilla users who follow the README's property API hit the same error. React 19 assigns custom-element props as properties when `name in node` is true, which it is here, so the React wrapper is exposed to the same failure. Scatter, stream, stacked-area, radial-bar and combo have the same pattern (mini-scatter-chart.js:70 and others).
- Rec: Never override only one half of an accessor. Move parsing into an overridable `static parseData(raw)` or `normalizeData(value)` hook, and keep a single getter/setter pair in the base class that stores the value (not only the attribute). Add a regression test that sets `el.data` on every registered element.

### [critical] components-bars-financial-2: `null` data crashes render (range-bar null item, bullet `data="null"`) (bug)
- Evidence: mini-range-bar-chart.js:80 `data.map((d) => Array.isArray(d) ? d[0] : (d.min || 0))`; mini-bullet-chart.js:82 `Array.isArray(data) ? data : [data.value || 0]`. The wrappers serialize null as-is: src/react/index.ts:233 `JSON.stringify(data)` (the default `[]` applies only to undefined); src/vue/index.ts:48. Probes: `Cannot read properties of null (reading 'min')` and `(reading 'value')`.
- Detail: Passing `null` while data is loading (`data={null}` / `:data="null"`) is a very common pattern. Range-bar also crashes when one item in the array is null, which happens with gaps or missing days. The exception is thrown inside connectedCallback or the render microtask, so the element stays blank and the error escapes to the page.
- Rec: Normalize data before anything reads it: non-arrays become an empty model, and null items become explicit gaps. Compute the label from the normalized model rather than the raw JSON. Add tests for null, undefined, {}, strings and nested garbage for every chart.

### [high] components-bars-financial-3: Interaction listeners are lost permanently after disconnect followed by reconnect (all six) (bug)
- Evidence: cleanup() detaches: mini-bar-chart.js:41-47, mini-win-loss-chart.js:58-64, mini-range-bar-chart.js:56-62, mini-bullet-chart.js:57-63, mini-candlestick-chart.js:57-63, mini-ohlc-chart.js:49-55. Re-attachment happens only on first build: bar L57-66 (`if (!svg || !style)`), win-loss L70-72→L123, range L82-84→L133, bullet L84-86→L156, candlestick L85-87→L122, OHLC L77-79→L117. Probe: listeners went from 2 (3 for candlestick) to 0 after reconnect.
- Detail: Moving the element in the DOM disconnects and reconnects it. This happens with keyed list reorders, drag and drop, portals, tab panels that detach content, and Vue KeepAlive. After that, hover and select events never fire again, even though the `interactive` CSS still shows hover affordances. The listeners sit on shadow-internal nodes owned by the element, so removing them on disconnect protects against no leak and only causes this bug.
- Rec: Attach listeners once, when the shadow DOM is built (or on the shadowRoot in the constructor), and stop detaching them in cleanup. If teardown is ever needed, make connectedCallback idempotent: re-attach whenever not attached. Add a reconnect test that counts dispatched events.

### [high] components-bars-financial-4: Observed attributes are read only on the first render: radius, hollow-bullish, wick-width and tick-width never update (bug)
- Evidence: mini-win-loss-chart.js:86 `const radius = this.getAttribute("radius") || "2"` inside #createDOM; mini-range-bar-chart.js:98; mini-candlestick-chart.js:102-103 (`hollow-bullish`, `wick-width`); mini-ohlc-chart.js:94 (`tick-width`). All of them are listed in observedAttributes (win-loss L22, range L24, candlestick L23-24, OHLC L16). Probe: radius changed from 2 to 8 and the CSS still read `2px`; `hollow-bullish="false"` still produced `fill: transparent`.
- Detail: The values are baked into the `<style>` text that #createDOM builds once. Later attribute changes trigger a render that ignores them. Reactive wrappers (signals, props) and theme or density toggles therefore silently do nothing. Bar avoids the problem because it rebuilds its style on every render, which is a different strategy (see the duplication finding).
- Rec: Drive per-instance values through custom properties set on internal nodes, or through `:host` inline custom properties written at update time (for example `svg.style.setProperty('--_radius', …)`). Keep the shared stylesheet static and use `var(--mini-chart-bar-radius, var(--_radius))`. Read every attribute in update(), never in createDOM().

### [high] components-bars-financial-5: `hollow-bullish` has inverted boolean semantics and cannot be turned off from React or Angular (api)
- Evidence: mini-candlestick-chart.js:102 `const isHollow = this.getAttribute("hollow-bullish") !== "false";` (an absent attribute means hollow). React drops false booleans: src/react/index.ts:258-260. Angular: mini-chart.directive.ts:506 (default false) and 526 `syncAttr(..., this.hollowBullish() ? "" : undefined)`, which removes the attribute. Undocumented in docs/components/mini-candlestick-chart.md.
- Detail: HTML boolean attributes are true when present and false when absent. Here both presence and absence mean hollow, and only the literal string "false" means solid. Both wrappers turn `false` into removing the attribute, so solid bullish candles are impossible from React or Angular. The value is also frozen after the first render (see the previous finding).
- Rec: Replace it with a positive opt-in such as `bullish-style="hollow|solid"` (default solid or hollow, documented), or a normal boolean `hollow` that is false when absent. Declare it in a typed attribute schema shared by the component and its wrappers.

### [high] components-bars-financial-6: win-loss `win-color`, `loss-color` and `tie-color` are documented, typed and observed but never implemented (api)
- Evidence: Observed at mini-win-loss-chart.js:24-26; there are no other references in the file (grep). Documented in docs/components/mini-win-loss-chart.md:19-21; typed at src/react/index.ts:173-178; Angular inputs at mini-chart.directive.ts:675-677 and synced at 696-698.
- Detail: Three public, typed attributes in all three wrappers have no effect. Users must discover the CSS variables instead. Each change also triggers a pointless re-render.
- Rec: Either implement them (map each attribute to an inline custom property on the svg, such as `--_win`, used as the fallback inside `--mini-chart-win-color`) or remove them from observedAttributes, the docs and the wrappers. Prefer one theming channel (CSS tokens) and avoid duplicating colors as attributes.

### [high] components-bars-financial-7: win-loss `mode` has three vocabularies: the code accepts 'status', the docs say 'binary', the React type says 'uptime' (api)
- Evidence: mini-win-loss-chart.js:183-185 `const mode = modeAttr === "status" ? "status" : "win-loss";`; docs/components/mini-win-loss-chart.md:18 '"binary" (default) or "status"'; src/react/index.ts:172 `mode?: "win-loss" | "uptime";`. Probe: `mode="uptime"` renders the win-loss layout.
- Detail: A TypeScript user who picks the typed value `uptime` gets the wrong chart and no warning. The docs name a value (`binary`) that the code never checks.
- Rec: Define the union once (for example `'win-loss' | 'status'`, optionally accepting `uptime` as an alias), export it as a type, generate the wrapper types and docs from it, and log a dev-mode warning for unknown values.

### [high] components-bars-financial-8: Bullet measure bar renders black with `gradient="false"` or a single color, which is what the Angular and Vue wrappers emit (theming)
- Evidence: mini-bullet-chart.js:118-120 `:host([gradient]) [part="measure"] { fill: unset; }`; L195 returns null for "false"; L204-207 returns null for a value without a comma (for example `gradient="#f00"`); L290 `this.#measureRect.style.fill = ""`. Angular: mini-chart.directive.ts:653 `syncJsonAttr(el, "gradient", ...)`, where L46-49 stringifies false to "false". Vue 3 sets `attr="false"` for false on non-boolean attributes.
- Detail: The selector `:host([gradient])` matches whenever the attribute is present, whatever its value. `fill` is an inherited property, so `unset` means inherit. Nothing up the tree sets `fill`, so it falls back to the initial value, black. Passing `[gradient]="false"` in Angular, `:gradient="false"` in Vue, or a single color therefore produces a black bar instead of the themed measure color. I traced this through the code and the CSS cascade; it should still be confirmed in a real browser.
- Rec: Toggle a class or state on the svg from JS (for example `data-gradient` only when stops resolve), not from the presence of the host attribute. Accept a single color. Make the default stops themable tokens (`--mini-chart-gradient-1..3`) instead of hex values hard-coded at L197.

### [high] components-bars-financial-9: Bullet data parsing: a valid JSON scalar renders 0, while `data=[]` draws a full chart labeled 'Empty' (data-model)
- Evidence: mini-bullet-chart.js:69-78 (JSON.parse first; the parseFloat fallback only runs when parsing fails); L228-255 handle only arrays and objects, so a number passes through unchanged; geometry.js:484-498 falls back to value 0 and target 0. L82 builds the label from `data.value`. Probes: `data="75"` gives aria-valuenow 0; `data="75%"` gives 75; `data="[]"` draws 3 range rects with label 'Empty Bullet chart'.
- Detail: The parseFloat fallback shows that a scalar value was meant to be supported, but only invalid JSON reaches it. A React `data={75}` becomes the string "75" and renders 0. Strings inside arrays or objects ("85") are also silently turned into 0. An empty input renders a misleading 0% bar instead of an empty state.
- Rec: Add a `normalizeBullet(input)` in core/data.js that accepts a number, `[value, target, ...ranges]` or `{value, target, ranges, min, max}`, coerces numeric strings explicitly (or rejects them with a dev warning), and returns `null` for empty input so the component can render a real empty state. Merge attributes after normalization and dispatch the merged model in events.

### [high] components-bars-financial-10: Candlestick/OHLC: extra row columns (volume, timestamp) pollute the scale domain; no object rows; no OHLC validation (data-model)
- Evidence: mini-candlestick-chart.js:73-75 and mini-ohlc-chart.js:65-67 accept `item.length >= 4`; geometry.js:184 `const allValues = values.flatMap(v => v);` uses every column for the domain. Probe: `[[100,110,90,105,1000000],…]` gives bodyHeight 0.5 and wick about 0 (a flat line).
- Detail: OHLCV (`[o,h,l,c,v]`) and `[t,o,h,l,c]` are the most common shapes returned by market APIs. With OHLCV, the volume dominates the domain and the chart collapses. With `[t,o,h,l,c]`, the timestamp is silently read as the open price. Objects (`{open,high,low,close}`) are filtered out without any warning. There is no check that high ≥ max(open,close) ≥ min(open,close) ≥ low. Filtering also shifts indices, so event `index` no longer matches the user's array.
- Rec: Add `normalizeOhlc(rows, {format})` that supports tuple formats via a `format="ohlc|tohlc|ohlcv"` attribute, plus objects `{open,high,low,close,time?,volume?}`. Use only o, h, l and c for the domain. Optionally repair high and low (or warn). Keep the original index in the normalized datum. Share one parser and layout between candlestick and OHLC.

### [high] components-bars-financial-11: Range-bar data model and docs drift: `{value}` is ignored (the code reads `current`), wrong part name, wrong default, nonexistent features (docs)
- Evidence: docs/components/mini-range-bar-chart.md:7 `{ min, max, value? }` vs geometry.js:674 `item.current`; doc:36 `part="range-marker"` vs mini-range-bar-chart.js:211 `part: "marker"`; doc:21 gap default 0.2 vs L189 0.25; doc:30,44 `--mini-chart-color-1` (not consumed anywhere in src) vs L104 `--mini-chart-range-color`; doc:3 'horizontal or vertical' (only vertical exists). Probe: `{min:10,max:30,value:22}` gives marker undefined.
- Detail: Users who follow the docs get no current-value marker and cannot style the marker or the bar color through the documented names. The component getter also accepts raw JSON with no validation (L68-76): string numbers become 0, and bare numbers become zero-height bars that drag 0 into the domain.
- Rec: Accept `value` and `current` (and `low`/`high`) in a dedicated `normalizeRanges`. Generate the docs from source annotations (@csspart, @cssprop, @attr) so names cannot drift. Document `--mini-chart-range-color`, `--mini-chart-marker-color/stroke` and `--mini-chart-bar-radius`.

### [high] components-bars-financial-12: Theming tokens are inconsistent across the group: four names for positive/negative, colliding meanings, different defaults, advertised tokens with no consumer (theming)
- Evidence: Bar: mini-bar-chart.js:82,85 `--mini-chart-positive-color`/`negative-color` (ignores bullish/bearish). Win-loss: mini-win-loss-chart.js:102-104 win/loss/tie, falling back to bullish/bearish/muted. Candlestick L110-111 and OHLC L105-106 use bullish/bearish. Collisions: `--mini-chart-range-color` is a background band in bullet (mini-bullet-chart.js:104) but the bar fill in range-bar (mini-range-bar-chart.js:104); `--mini-chart-danger-color` is the gauge danger zone (mini-gauge-chart.js:24) but the bullet target (mini-bullet-chart.js:122). Defaults: svg.js:7 #2563eb, bar positive #10b981 (L82), range and bullet #3b82f6, README.md:150 says #0ea5e9. `--mini-chart-color-1..8` are advertised (README.md:151, docs/architecture.md:34, demo/app.js:706, bar doc:18-19, bullet doc:25) with no consumer in src. Bar shadows `--mini-chart-fill` (svg.js:32-35, overridden at L81-86). Radius: bar uses the attribute only (rx attribute, default 0), win-loss uses a var with default 2, range-bar a var with default 3, bullet a hard-coded 2px (L113).
- Detail: Setting one dashboard-level token gives unpredictable results. `--mini-chart-range-color` recolors range bars and also bullet bands. Setting `--mini-chart-bullish-color` affects candles and win-loss but not bar positives. With no tokens set, a bar chart is green while a line chart is blue. This blocks the 'real theming system' goal and makes dark mode impossible to define in one place.
- Rec: Define a token spec: semantic tokens (`--mini-chart-accent`, `--mini-chart-positive`, `--mini-chart-negative`, `--mini-chart-neutral`, `--mini-chart-band-1..3`, `--mini-chart-radius`, `--mini-chart-mark-opacity-inactive`, `--mini-chart-palette-1..8`) that per-component tokens fall back to, with the old names kept as aliases for one major version. Use one default palette module (palette.js) and generate the token table in the docs from source.

### [high] components-bars-financial-13: Bullet bands depend on the global, non-namespaced `--primary` (theming)
- Evidence: mini-bullet-chart.js:108-110 `color-mix(in srgb, var(--primary, #3b82f6) 12%, …)`; also mini-scatter-chart.js:104.
- Detail: Custom properties inherit through the shadow boundary, so any host page that defines `--primary` changes the bullet bands. Many design systems do (shadcn/ui v3 even uses raw HSL channels such as `--primary: 222.2 47.4% 11.2%`). If that value is not a valid color, the `color-mix()` is invalid at computed-value time and `fill` falls back to inherit, which renders the bands black. The behavior depends entirely on the host app's naming.
- Rec: Only consume `--mini-chart-*` tokens. Fall back to `--mini-chart-accent` (or currentColor) and never to unprefixed globals.

### [high] components-bars-financial-14: Inconsistent event contracts; `sparkline-select` not reachable from wrappers; internal shadow nodes leaked in detail (api)
- Evidence: Bar mini-bar-chart.js:110-114 {index,value,isPositive,element}; win-loss L136-140 {index,value,outcome,element}; range L145-149 {index,data(raw),element}; bullet L164-168 {data(raw, pre-merge),element}; candlestick L140-154 plus `sparkline-select` L172-186; OHLC L135-148 (no element, no select). Wrappers: src/react/index.ts:32-37 (no onSparklineSelect; the handlers are destructured and dropped at L224-227); src/vue/index.ts:41 emits list; Angular mini-chart.directive.ts:513-514 (no select output).
- Detail: The same event name carries six different detail shapes and no typed event map, so framework users cannot write one generic tooltip. Bullet's detail ignores the `target`/`min`/`max`/`ranges` attribute overrides. Range-bar returns the raw user item (which may be malformed). Every composed event carries `element`, an internal shadow node, which breaks encapsulation and ties consumers to internal markup. The candlestick select event exists only for raw `addEventListener` users.
- Rec: Define one contract: `mini-chart-hover`, `mini-chart-leave` and `mini-chart-select` with `detail: { chartType, index, datum /* normalized */, raw, anchor: DOMRect }`. Declare the events with JSDoc `@fires` and generate React, Vue and Angular bindings and types from that manifest. Add select (click and Enter) to every component in the group.

### [medium] components-bars-financial-15: Out-of-domain values are not clamped and the svg has `overflow: visible`; min > max inverts the chart (bug)
- Evidence: svg.js:20 `overflow: visible`; bar min/max L153-156 into geometry.js:31-46 (no validation); range-bar geometry.js:685-686; candlestick/OHLC geometry.js:185. Probes: bar `min=50`, data [10,20] gives y=-6.67 (inverted); `max=100` with value 200 gives y=-24.
- Detail: Shared scales across table rows (for example `max=100` with one outlier at 120) make bars, wicks and ranges draw outside the host box, over neighboring content. `min` greater than the data maximum (or greater than `max`) silently flips the scale. Only bullet clamps (geometry.js:521,538,552).
- Rec: Validate the domain in one place (swap or ignore min > max with a dev warning) and clamp projected values to the plot area. Optionally flag clipped marks with a part (`clipped`) so they can be styled. Consider `overflow: hidden` on the svg for bar-type charts, or a clipPath.

### [medium] components-bars-financial-16: Entrance stagger grows linearly with data length (365 points means about 11 s); reduced-motion does not cancel the inline delays (perf)
- Evidence: mini-bar-chart.js:211 `${index * 0.03}s`, timer L217 `400 + bars.length * 30 + 50`; win-loss L235 (0.025·i); range L249; candlestick L292-293; OHLC L242. svg.js:55-62 reduced-motion sets only `transition-duration`, not the delay.
- Detail: Daily data for a year (365 points) means the last bar appears about 11 s after mount, and the cleanup timer keeps running just as long. Users who prefer reduced motion still see bars pop in one by one, because the inline `transition-delay` is untouched.
- Rec: Cap the total stagger (for example `delay = (i / n) * 300ms`). Skip the entrance animation when `matchMedia('(prefers-reduced-motion: reduce)')` matches or n exceeds a threshold. Centralize this in one `animateEntrance()` helper, using WAAPI or `@starting-style` instead of setTimeout plus forced reflow.

### [medium] components-bars-financial-17: Bar's entrance animation trigger differs from the rest of the group; bar rebuilds its stylesheet on every render (bug)
- Evidence: mini-bar-chart.js:55 `const isInitialRender = !svg;` versus win-loss L206, range L206, candlestick L246, OHLC L206 `isInitial = cache.length === 0`. Bar L73-96 rewrites `style.textContent` on every render.
- Detail: Bar's first render is often empty, for example when the element connects before Angular effects or async data set `data`. In that case the bar chart never animates in, while the sibling charts do. Rewriting the CSS text on every attribute change forces style recalculation for the whole shadow tree.
- Rec: Use one base-class rule: animate on the first non-empty model, and keep the stylesheet static (preferably a shared constructable stylesheet via `adoptedStyleSheets`).

### [medium] components-bars-financial-18: Bar `baseline` attribute is observed and typed in React and Angular but never read (api)

### [high] components-bars-financial-19: Base `data` setter double-encodes strings, so React 19 property assignment empties bar and win-loss charts (bug)
- Evidence: src/core/mini-chart-element.js:49-51 `this.setAttribute("data", JSON.stringify(values))`; src/react/index.ts:233 passes `data` as a string. Probe: `bar.data = "[1,2,3]"` sets the attribute to `"[1,2,3]"` (with quotes), and the parsed data is `[]`.
