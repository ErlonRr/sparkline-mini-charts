# core

## Summary
I read the core layer (mini-chart-element.js, svg.js, data.js, palette.js, registration.js, define.js, index.js, register.js) and all 17 components in full. MiniChartElement is a thin shell, and in practice every component goes around it. All 17 override render(), so the base render() and the abstract renderChart() are never called. Three components (bar, pie, half-pie) declare a renderChart(svg, data, isInitial) whose signature doesn't match the base. Each component re-implements the same scaffolding by hand: DOM skeleton, per-instance <style>, double-rAF/setTimeout animation, pointer listeners, sparkline-hover/leave dispatch, attribute parsing, gradient parsing and element pooling. About 2,100 of the 4,810 non-empty component lines (~44%) appear verbatim in at least one other component. Five near-clone pairs share 88-96% of their lines: line/area, pie/half-pie, stacked/stream, gauge/progress, candlestick/ohlc.

There are several confirmed defects.
- **Data setter throws:** 9 components override only `get data()`, which drops the inherited setter. `el.data = x` throws a TypeError in strict code (I checked this in node). The Angular directives do exactly that for all 17 charts.
- **Reduced motion shows wrong values:** the reduced-motion CSS forces `stroke-dashoffset: 0 !important`. Progress and radial-bar charts then always look 100% full.
- **Hover dies after a DOM move:** every component removes its listeners in cleanup() but never re-attaches them on reconnect.
- **Entrance animations cancelled:** an element upgraded while already in the page renders twice. The second render cancels the entrance animation in 8 components.
- **Inline colour wiped:** trend-color writes to the host's inline style and removes the user's own `--mini-chart-color`.
- **Data misaligned:** normalisation filters out invalid entries, which shifts indices and misaligns stacked series.
- **Crashes on null:** bullet, range-bar and scatter throw on null data.
- **Stale rings:** radial-bar leaves old rings visible when the data gets shorter.

Lifecycle, styling and theming:
- Six attributes are read only once and then go stale, and four declared attributes are never used.
- Styles are a per-instance <style> string, rewritten on every render in bar, pie and half-pie, and unique per instance in five components (which defeats the browser's style sharing). Nothing uses adoptedStyleSheets, and `:host([hidden])` is missing.
- Theme token names collide across components: `--mini-chart-stroke-width` and `--mini-chart-range-color` mean different things in different charts, and the app-level `--primary`/`--surface` leak into component CSS.
- The SSR guard lets the code be imported on the server, but there is no server rendering path. attachShadow is called unconditionally, so declarative shadow DOM is wiped.

Accessibility amounts to role=img plus a label that only counts the values. Interactive charts can't be reached by keyboard.

The 17 hover-event detail shapes all differ, and the event names don't line up with the wrappers. Vue and Angular listen for `slice-select`, which no chart ever fires. Candlestick's `sparkline-select` and progress's `progress-complete` aren't passed through by them at all. The test harness mocks the DOM and sets attributes before connecting, so none of these lifecycle paths are tested.

## Proposals
- 1. Typed property/attribute descriptor system (core/props.js). `static properties = { data: data(NumericSeries), min: num(), max: num(), curve: enumOf(['linear','smooth','step','step-before','step-after'],'linear'), interactive: bool(), gradient: colorList(), referenceValue: num({attribute:'reference-value'}) }`. The base generates observedAttributes (inheriting base props such as label/locale/animate), get/set accessors (no getter-only overrides; data stored in a private field, not reflected), attribute→property parsing cached once per change, the upgrade-property fix in connectedCallback, dev-mode coercion warnings, and a changed-keys set passed to update(). The same descriptors produce the React/Vue/Angular wrapper props and TS types and the docs attribute tables. Used by all 17 components; it removes the 38 parseFloat sites, the 9 data-getter overrides and the 17 hand-written observedAttributes lists.
- 2. Data model and normalisers (core/data/). Typed, index-preserving models: NumericSeries ((number|null)[] + gap policy), MultiSeries (column-aligned), OhlcSeries ({o,h,l,c,valid}[]), RangeSeries, PointSeries ({x,y,r}), ComboSeries, RadialSeries ({value,color?}), BulletDatum, MeterDatum (value/min/max). Each has `normalize(raw) -> {model, issues[]}` with no throwing and no index shifting. Parsed once, cached, frozen. The default label summariser and event `datum` come from the model. Used by: NumericSeries → line, area, bar, win-loss, pie, half-pie; MultiSeries → stacked, stream; OhlcSeries → candlestick, ohlc; RangeSeries → range-bar; PointSeries → scatter; ComboSeries → combo; RadialSeries → radial-bar; MeterDatum/BulletDatum → gauge, progress, bullet.
- 3. New MiniChartElement lifecycle (template method). Constructor: `this.shadowRoot ?? attachShadow` (DSD-aware), styles adopted. First connect: `createStructure(root)` once. Every change: `requestUpdate()` with dedupe (connectedCallback also goes through the scheduler, which fixes the double render). `update(model, changed)` implemented by the subclass. Connection-scoped AbortController for any external listeners/observers. Error boundary → `sparkline-error` event + empty state. `updateComplete` promise for tests/frameworks. Optional ResizeObserver/IntersectionObserver hook to defer the first render of off-screen charts. Replaces the 17 render() overrides and cleanup() copies (~500 lines).
- 4. StyleSheet registry + token contract (core/styles.js, core/tokens.js). One cached CSSStyleSheet per class via adoptedStyleSheets (<style> fallback), no runtime string interpolation (variants via `:host([attr])` selectors and internal custom properties), base sheet fixes (`:host([hidden])`, reduced-motion handling without stroke-dashoffset). A single token table (names, defaults, scope) generates the CSS defaults and docs, with semantic tokens (accent, positive, negative, neutral, track, grid, text, series-1..16) and component-scoped tokens (e.g. --mini-chart-gauge-track-width, --mini-chart-bullet-band-color) so names don't collide. `MiniChartElement.adoptGlobalStyles(sheet)` hook for theme packs. Used by all 17 components; removes the per-instance <style> in 17 files and the per-render rewrites in bar/pie/half-pie.
- 5. AnimationController (core/animation.js). WAAPI-based: `reveal.clip(rect)` (line, area, combo, stacked, stream), `stagger(nodes, from, to)` (bar, candlestick, ohlc, combo-bars, radial-bar, range-bar, scatter, win-loss), `tween(node, prop, from, to)` (bullet measure, gauge needle, progress arc, pie/half-pie mask), `morphPath(prevPoints, nextPoints)` with JS interpolation (line, area, stacked, stream). It respects prefers-reduced-motion and an `animate` attribute, cancels on update or disconnect, and needs no forced reflows or setTimeout cleanup. Removes 19 getBoundingClientRect calls, 16 rAF calls and 14 setTimeout calls.
- 6. InteractionController (core/interaction.js). Strategies: `nearestX(points)` (line, area, combo, stacked, stream), `hitTarget(selector → index)` (bar, candlestick, ohlc, pie, half-pie, radial-bar, range-bar, scatter, win-loss), `whole()` (gauge, progress, bullet). It delegates once on the shadowRoot (survives reconnect), handles pointer + keyboard (roving index, arrows/Home/End, Enter → select), renders the shared crosshair/active-marker overlay, de-duplicates same-index events, announces through a live region, and emits typed events from core/events.js with a uniform detail {index, seriesIndex, value, datum, clientX, clientY, svgX, svgY} and no shadow-node leaks. Removes ~700 lines of handlers/setup/detach.
- 7. Event contract module (core/events.js). Constants (SPARKLINE_HOVER, SPARKLINE_LEAVE, SPARKLINE_SELECT, ZONE_CHANGE, PROGRESS_COMPLETE, SPARKLINE_ERROR), JSDoc typedefs, `HTMLElementEventMap` augmentation, and `dispatch(el, name, detail)`. React/Vue/Angular wrappers generate their outputs/emits from it, which fixes the slice-select mismatch and the missing sparkline-select/progress-complete pass-through.
- 8. Shared SVG primitives (core/svg/). `keyedPool(container, factory)` with grow/hide/remove-surplus (fixes the radial stale rings; used by bar, candlestick, ohlc, combo, pie, half-pie, radial, range-bar, scatter, stacked, stream, win-loss, line/area points), `createClip(defs)`, `createGradient(defs, stops)` + `parseColorList()` tokenizer (area, bullet, gauge, progress, radial), deterministic `uid()`, a `ReferenceLine`/`Baseline` overlay using scales returned by geometry (line, area, win-loss, future bar), and a `seriesColor(i)` helper that resolves through CSS (pie, half-pie, radial, stacked, stream).
- 9. Chart families by composition, so near-clones collapse. CartesianSeriesChart (line + area via `fill`; combo reuses its line layer), RadialSlicesChart (pie + half-pie via `sweep`/`start-angle`, implementing pad-angle), StackedChart (stacked + stream via `offset`), FinancialChart (candlestick + ohlc via a glyph renderer), MeterChart (gauge + progress + bullet sharing value/min/max/aria-meter/gradient/valuetext), DiscreteBarsChart (bar + win-loss + range-bar sharing slot layout and the stagger). Expected shrink from ~4,800 to ~2,000 component lines.
- 10. Accessibility layer (core/a11y.js). ElementInternals for host role/name (img/meter/group), the internal svg aria-hidden, a label summariser per data model (count, min, max, last, change %) with a `locale` property + Intl.NumberFormat, aria-valuetext with unit, honouring host aria-label/aria-labelledby, and an optional visually-hidden data table slot. Wired to the InteractionController for keyboard navigation and announcements.
- 11. SSR and registration. A pure `renderToString(tag, props)` built on geometry + the same structure builders (string backend) emitting DSD, hydration-aware createStructure, an exported `:not(:defined)` sizing stylesheet, `defineMiniCharts({prefix, registry})` with subclass aliasing, a `static version` collision warning, and exports of MiniChartElement + controllers as the extension API.
- 12. Suggested backlog order: P0 hotfixes (data setter, reduced-motion dashoffset, reconnect listeners, double render, trend-color host style, radial surplus, null crashes, :host([hidden])); P1 foundations (props descriptors → data models → lifecycle → event contract, with real-browser lifecycle tests); P2 controllers (styles/tokens, animation, interaction, pools) migrated one family at a time; P3 families merge, a11y layer, SSR/DSD, wrapper codegen from descriptors.

## Findings

### [critical] core-1: Getter-only `data` override removes the setter in 9 components; `el.data = x` throws (breaks Angular wrappers) (bug)
- Evidence: src/core/mini-chart-element.js:44-51 (base get+set); own getter without setter: mini-bullet-chart.js:69, mini-candlestick-chart.js:69, mini-combo-chart.js:79, mini-ohlc-chart.js:61, mini-radial-bar-chart.js:78, mini-range-bar-chart.js:68, mini-scatter-chart.js:70, mini-stacked-area-chart.js:74, mini-stream-chart.js:73. Angular assigns the property: src/angular/mini-chart.directive.ts:235, 271, 390, 522, 564, 604, 645, 732, 775, 847 (`if (d !== undefined) el.data = d;`). Checked in node: `Object.getOwnPropertyDescriptor(MiniCandlestickChart.prototype,'data').set === undefined`; strict-mode assignment -> `TypeError: Cannot set property x of #<B> which has only a getter`.
- Detail: In JS classes, declaring only `get data()` in a subclass creates a new accessor whose setter is undefined, hiding the base getter/setter pair. ES modules and Angular-compiled code run in strict mode, so `el.data = [...]` throws a TypeError for bullet, candlestick, combo, ohlc, radial-bar, range-bar, scatter, stacked-area and stream. In Angular the effect fails, the error goes to ErrorHandler, and the chart never receives data. In vanilla JS the documented-looking `chart.data = ...` property API crashes. The tests only use setAttribute (test/components.test.js:218-224), so this went unnoticed.
- Rec: Move parsing out of accessors: the base owns a single `data` get/set pair backed by a private `#model`, and each subclass supplies a static `dataSchema`/`normalize(raw)` hook instead of overriding the accessor. Add a regression test that assigns `el.data = ...` on every component.

### [critical] core-2: Reduced-motion rule forces stroke-dashoffset:0 !important, so progress and radial-bar always look 100% full (bug)
- Evidence: src/core/svg.js:55-62 (`*, *::before, *::after { ... stroke-dashoffset: 0 !important; }`). The value is encoded in dashoffset: mini-progress-chart.js:147-153 (pathLength 100, dasharray 100), 290, 294, 298 (`style.strokeDashoffset = String(targetOffset)`); mini-radial-bar-chart.js:267-271, 293, 323, 354.
- Detail: Author `!important` beats normal inline styles. With `prefers-reduced-motion: reduce` (macOS/iOS Reduce Motion, Windows animations off), every progress arc and radial ring has dashoffset 0, so it is fully drawn whatever the value. 30% progress shows as 100%. A rule meant to suppress animation is changing the data shown, for a large group of users.
- Rec: Remove `stroke-dashoffset` from the global reduced-motion rule. Handle reduced motion in a shared animation controller (skip the entrance and jump to the final state) and also zero `transition-delay`. Add a visual test that runs with reduced motion emulated.

### [high] core-3: Interactivity is permanently lost after any disconnect/reconnect (17/17 components) (bug)
- Evidence: cleanup() detaches listeners: mini-line-chart.js:73-76, 224-227; DOM build + listener attach only behind build-once flag: mini-line-chart.js:95-98, 166. Same pattern: area:80-83/101-104/197; bullet:57-63/84-87/156; candlestick:57-63/85-88/122; combo:63-73/99-102/175; gauge:96-102/108-111/202; ohlc:49-55/77-80/117; progress:66-72/78-81/165; radial:66-72/96-99/147; range-bar:56-62/82-85/133; scatter:58-64/84-87/135; stacked:58-68/90-93/146; stream:57-67/89-92/145; win-loss:58-64/70-73/123; svg-existence variant: bar:41-47/53-66, pie:49-55/61-89, half-pie:47-53/59-87. Base: mini-chart-element.js:53-59.
- Detail: disconnectedCallback → cleanup() removes the pointermove/pointerover/pointerleave/click listeners. On reconnect, connectedCallback → render() finds `#initialized === true` (or an existing svg), skips the DOM-creation step, and never re-attaches them. Moving an element (keyed list reorder in React/Vue/Angular, portals/Teleport, KeepAlive, CDK drag-drop, moving into a dialog) silently stops `sparkline-hover`/`sparkline-leave`/`sparkline-select`. Detaching wasn't needed in the first place: the listeners sit on the element's own shadow nodes, so they can't leak. docs/architecture.md:28 presents this detaching as leak protection.
- Rec: Attach listeners once, delegated on the shadowRoot, in the constructor or first build, and don't remove them on disconnect. Or use an AbortController created in connectedCallback and aborted in disconnectedCallback. Keep 'structure built' separate from 'connected'. Add a real-browser test: connect, disconnect, reconnect, then dispatch a pointer event.

### [high] core-4: Upgrade path renders twice; the second render cancels entrance animations and re-fires events (bug)
- Evidence: mini-chart-element.js:53-55 (sync render on connect), 61-74 (attributeChangedCallback queues microtask when isConnected). Cancellation on second pass: mini-line-chart.js:254 + 378-401; mini-area-chart.js:304 + 482-507; mini-combo-chart.js:246-249 + 355-369; mini-stacked-area-chart.js:215-218 + 277-298; mini-stream-chart.js:214-217 + 273-294; mini-bullet-chart.js:215-218 + 307-317; mini-gauge-chart.js:286-289 + 402-412; mini-progress-chart.js:227-230 + 285-295; re-dispatch mini-progress-chart.js:302-308.
- Detail: When `define()` upgrades an element already in the page (the default `<script type=module>`/register.js setup), attributeChangedCallback runs for each attribute with `isConnected === true`, so a microtask render is queued. connectedCallback then renders synchronously, and the microtask renders a second time. On that second pass each `#updateChart` cancels the pending double-rAF/timeout and takes the non-initial branch. Clip reveals snap to full width (clipRect still has `transition:none`). The needle, progress and bullet changes happen in the same frame as the 'from' state, so there's no transition. On page load this doubles work for every chart, and `progress-complete` fires twice. The mock test sets attributes before `isConnected = true` (test/components.test.js:218-224), so this order is never exercised.
- Rec: Use a single scheduler: connectedCallback calls `requestUpdate()`, or renders synchronously and clears any queued flag through a render token, so a queued microtask is skipped if a render already happened. Add dirty tracking (a set of changed props) and an `updateComplete` promise. Only dispatch state events like progress-complete on transitions (prev < max ≤ next), never on re-renders.

### [high] core-5: trend-color writes to the host's inline style and wipes the user's --mini-chart-color (theming)
- Evidence: mini-line-chart.js:282-292 and mini-area-chart.js:334-344 (`this.style.setProperty("--mini-chart-color", ...)` / `this.style.removeProperty("--mini-chart-color")` on every render).
- Detail: On every render where trend-color isn't `auto`, the component calls `this.style.removeProperty('--mini-chart-color')` on the host. That deletes an author's `<mini-line-chart style="--mini-chart-color: hotpink">` and any value set by React `style={{'--mini-chart-color':...}}` or Vue `:style`. Frameworks won't re-apply it until their own value changes. The component is mutating its own light-DOM style attribute, which breaks the rule that the host's attributes belong to the consumer.
- Rec: Compute the trend internally: set `data-trend="up|down"` on an internal wrapper (or a custom state through `ElementInternals.states`) and map it in the shadow CSS: `:host([trend-color=auto]) .root[data-trend=up]{color:var(--mini-chart-bullish-color,…)}`. Never touch `this.style`.

### [high] core-6: Data normalisation drops invalid entries, shifting indices and misaligning stacked series (data-model)
- Evidence: src/core/data.js:17 (`parsed.filter(...)`); mini-stacked-area-chart.js:78-80 and mini-stream-chart.js:77-79 (`series.filter(Number.isFinite)` per series); mini-candlestick-chart.js:73-75; mini-ohlc-chart.js:65-67; mini-combo-chart.js:83-89; mini-radial-bar-chart.js:82-86. Geometry would have treated gaps as 0 at the right index: src/core/geometry.js:382, 393 (`series[j][i] || 0`). Hover reports the filtered index: mini-line-chart.js:187-188, 204.
- Detail: `[1, null, 3]` becomes `[1, 3]`: the line is drawn with two evenly spaced points, and the gap and x-position are lost. Hover then reports `index:1, value:3` while the consumer's array has 3 at index 2. For stacked/stream, `[[1,null,3],[4,5,6]]` turns series 0 into `[1,3]`, so column 1 stacks 3 on top of 5 and column 2 stacks 0 under 6. The chart shows values that aren't in the data. Missing values are routine in time series, so this blocks the 'solid data structures' goal.
- Rec: Introduce typed normalisers that keep indices: `NumericSeries = (number|null)[]` with an explicit gap policy (`gaps="break|zero|interpolate"`), aligned `MultiSeries` (pad or null per column), and OHLC/range/point records with a `valid` mask. Event details should report the source index plus the original datum.

### [high] core-7: No property-upgrade handling, and the property path round-trips through a JSON attribute (architecture)
- Evidence: mini-chart-element.js:44-51 (getter parses the attribute on every access; setter runs `JSON.stringify` into the attribute), 53-55 (no `#upgradeProperty`). Wrappers stringify too: src/react/index.ts:233, 257; src/vue/index.ts:48; src/angular/mini-chart.directive.ts:49 (syncJsonAttr) and 104 (property).
- Detail: If `el.data = [...]` (or `label`, etc.) is assigned before the element is defined (lazy or code-split `register`, or a framework rendering before the define import), the value becomes an own property on the instance and shadows the prototype accessor forever. The chart renders empty, and later assignments never trigger a render. Even when defined, each update runs stringify, attribute write, attributeChanged, microtask and parse, so large or live series are serialised twice. `el.data !== el.data` on every access. Objects like Date, extra fields or color metadata lose fidelity. A multi-framework library should treat properties as the primary channel and attributes as the declarative fallback.
- Rec: Base class: in connectedCallback, run `for (const p of this.constructor.properties) if (Object.hasOwn(this,p)) { const v=this[p]; delete this[p]; this[p]=v; }`. Store `data` in a private field (no reflection to the attribute). Parse the attribute only in attributeChangedCallback, once, into the same field. Update the wrappers to set the property instead of stringifying.

### [high] core-8: The base-class abstraction is bypassed: 17/17 override render(), and ~44% of component code is duplicated (architecture)
- Evidence: Base render/renderChart unused: mini-chart-element.js:83-92, 112-114. Overrides: line:91, area:97, bar:50, bullet:80, candlestick:81, combo:95, gauge:104, half-pie:56, ohlc:73, pie:58, progress:74, radial-bar:92, range-bar:78, scatter:80, stacked-area:86, stream:85, win-loss:66. Incompatible `renderChart(svg, data, isInitial)`: bar:142, pie:164, half-pie:162. 2,097 of 4,810 non-empty lines repeated across files; near-clones line/area 88%, pie/half-pie 91-94%, stacked/stream ~95%.
- Detail: The base renders by full replacement (`replaceChildren(style, svg)`), which no animated chart can use, so each component built its own lifecycle: build-once flag, label/title sync, cleanup, listeners, animation timers and pools. Fixes have to be applied up to 17 times, and they already drift: radial-bar doesn't hide surplus tracks while stacked does; candlestick/ohlc/stacked/stream skip the aspect-ratio line; combo only supports linear/smooth curves while line/area support step; combo recreates its point on every render (combo:375-385), so its CSS transition never runs. observedAttributes are restated by hand in every class (e.g. line:19-29) instead of extending the base list (l.14).
- Rec: Redesign the base as a template method: `static properties` (descriptor), `createStructure(root)` once, `update(model, changed)` per render, plus shared controllers (animation, interaction, styles, pools). Merge the near-clones into families: CartesianSeries (line+area), RadialSlices (pie+half-pie), Stacked (stacked+stream), Financial (candlestick+ohlc), Meter (gauge+progress+bullet). See proposals.

### [high] core-9: Invalid data crashes render (null entries / null JSON) with no error boundary (bug)
- Evidence: mini-bullet-chart.js:69-78 (raw JSON.parse, any type) + 82 (`data.value` throws for `data="null"`); mini-range-bar-chart.js:68-76 (unvalidated) + 80 (`d.min` throws on `[null]`); mini-scatter-chart.js:70-78 + 82 (`d.y` throws on `[null]`). Base: no try/catch around render (mini-chart-element.js:53-55, 70-73). Also mini-bullet-chart.js:74-77: `data="42"` is valid JSON → number → geometry ignores it (geometry.js:484-498) → renders 0; the parseFloat fallback can't be reached.
- Detail: The geometry layer handles nulls (geometry.js:662-680, 759-770), but each component computes its default label before calling geometry and dereferences null there. The TypeError escapes connectedCallback or the microtask, the element stays blank or half-updated, and nothing reports it besides window.onerror. Elsewhere, bad input fails silently: malformed JSON gives an 'Empty X chart' with no developer warning.
- Rec: Validate in the per-chart normaliser (one place) and never dereference raw parsed values in components. Wrap `update()` in a base error boundary that logs a dev warning with the element, dispatches a `sparkline-error` CustomEvent, and renders an empty or fallback state.

### [high] core-10: Radial-bar leaves stale rings visible when the data gets shorter (bug)
- Evidence: mini-radial-bar-chart.js:335-372 (update branch iterates only the new `tracks`; nothing hides `this.#tracks[i]` for i >= tracks.length) versus 225-230 (only empty data hides all). Compare mini-stacked-area-chart.js:272-275, which does hide surplus layers.
- Detail: Going from `[80,60,40]` to `[80,60]` keeps the third ring drawn at its old value, and hovering it reports `value: 0` because `#currentData[2]` is undefined (l.156-157). This is out-of-date data on screen.
- Rec: Use a shared keyed pool helper that always hides or removes surplus nodes; radial-bar would then get the fix automatically.

### [high] core-11: No central event contract: 17 detail shapes, shadow internals leaked, wrapper event names that don't match (api)
- Evidence: Detail shapes: line:201-205, bar:110-114, combo:205-215, bullet:164-168, candlestick:140-154 + 172-186 (`sparkline-select`), ohlc:135-148 (no `element`), gauge:210-218 + 384-392, progress:173-180 + 302-308, pie:132-136, half-pie:130-134, radial:160-164, range-bar:145-149, scatter:147-151, stacked:158-162, stream:157-161, win-loss:136-140. Wrappers listen for `slice-select`, which nothing emits: src/angular/mini-chart.directive.ts:67-68, src/vue/index.ts:41, 52.
- Detail: Consumers can't write one tooltip handler. `x/y` are viewBox units, which aren't useful for positioning without the svg rect. `element` hands a shadow-internal node out through a composed event, so internal structure becomes public API. Index keys differ (`index` / `trackIndex` / `layerIndex`). Line, area, combo, gauge and progress dispatch on every pointermove even when the index hasn't changed, and gauge and progress call getBoundingClientRect on every move (gauge:207, progress:170). Vue and Angular expose a `slice-select` output that never fires, while `sparkline-select` and `progress-complete` aren't passed through. The lack of a typed contract is what stops the wrappers from being generated reliably.
- Rec: Create core/events.js with event-name constants, JSDoc typedefs and an `HTMLElementEventMap` augmentation. Use a uniform detail `{ index, seriesIndex?, value, datum, clientX, clientY, svgX, svgY }`, drop `element`, and dispatch only when the index changes. Generate the wrapper outputs/emits from this module.

### [high] core-12: Theme tokens collide or leak between components, and event colours ignore CSS overrides (theming)
- Evidence: `--mini-chart-stroke-width`: svg.js:28 (line, 2) vs mini-gauge-chart.js:129 (14) vs mini-progress-chart.js:100/106 (12). `--mini-chart-range-color`: mini-bullet-chart.js:104 (grey band) vs mini-range-bar-chart.js:104 (bar fill). App-level `--primary`/`--surface`: mini-bullet-chart.js:108-110, mini-scatter-chart.js:104, 111. Two default blues: svg.js:7 / combo:124 / gauge:132 `#2563eb` vs bullet:112 / progress:105 / range-bar:104 / scatter:110 `#3b82f6`. JS hex in event details: pie:130, half-pie:128, radial:158, stacked:156, stream:155.
- Detail: Setting `--mini-chart-stroke-width: 3` on a dashboard container to thicken lines also turns gauges and progress tracks into hairlines. Setting `--mini-chart-range-color` changes two unrelated things. The components read unprefixed `--primary`/`--surface` from whatever host app they're dropped into. When a consumer themes `--mini-chart-color-2`, the tooltip still gets the default palette hex. Defaults are hard-coded hex values spread across 17 files with no single source of truth.
- Rec: Define a token contract module (names, defaults and scope: global vs per-component such as `--mini-chart-gauge-track-width`) and build the CSS from it. Drop the unprefixed tokens. Resolve series colours CSS-first (read `getComputedStyle(segment).fill` for event details). Document semantic tokens: accent, positive, negative, neutral, track, grid, text.

### [high] core-13: Interactive charts can't be used from the keyboard and have no focus or announcements (a11y)
