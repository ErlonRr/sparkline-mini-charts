# geometry

## Summary
The geometry module (src/core/geometry.js, 839 lines) is pure and has no dependencies, which makes it a good base for a multi-framework library. As it stands, though, it is a flat file of 18 functions plus TAU with no internal layering. Every symbol is frozen as public API twice: once through the root index (src/index.js:23-44) and once as the whole file under "./math" (vite.config.js:33). That includes chart-specific layouts whose output shapes hard-code presentation ratios.

I confirmed several correctness bugs by running node on the module:
- Combo chart: the line vertices do not line up with the bar centres, because the bars use band (slot) positions and the line uses point positions.
- Candlestick: the domain is built from every element of each tuple. An OHLCV row squashes all candles to the bottom of the chart, and a date-string fifth element turns every coordinate into NaN.
- Smoothing: the uniform Catmull-Rom curve overshoots. It dips below the zero baseline and nearly reaches the viewBox edge on common data such as [0,0,0,10,10,10].
- min/max: explicit values are not checked. min above the data maximum flips the chart and puts points outside the canvas, and nothing is clamped while the SVG has overflow:visible.
- Stacking: negative values overlap other layers. Expand mode mixes percentages with raw values. The stacked/stream data getters filter out non-finite values per series, which shifts columns out of alignment.
- Arcs: the sweep flag is always 1 and full circles ignore startAngle. A slice of about 99.9999% vanishes because of 3-decimal rounding.
- Regression: the naive sums lose precision, so the trend line disappears for millisecond timestamps one second apart.
- Large arrays: Math.min/max(...spread) throws a RangeError at about 125k values.

On structure:
- formatNumber is private, so components build linear, area, morph and OHLC paths by hand with 16-17 digit floats. Path strings come out about 2.4x larger than with the module's 3-decimal rounding.
- There is no linear-path generator, no band scale, no scale.invert, no `defined`/gap support, x is always the point index, and there is no downsampling.
- Padding and radius constants (2/4, 48/46/44/40, centre 50/50) are copied into components.
- Option names, defaults and return shapes differ from one function to the next.

Tests exist for 14 of the 18 functions, but the assertions are weak; for example, the stacked layout test checks only array lengths. createCandlestickLayout, describeArc, createRadialBarLayout and polarToCartesian have no tests. docs/architecture.md wrongly says the tests use Vitest and cover NaN and negative-baseline edge cases.

Recommended direction: split the module into scale/, shape/, layout/, stats/, sample/ and path/. Keep only the primitives public under "./math". Make the chart-specific layouts internal or experimental. Add a renderer-independent chart model that the Web Components, the React/Vue/Angular wrappers and SSR can all share.

## Proposals
- Module layout: replace src/core/geometry.js with src/math/ split by concern. (a) scale/: linear.js (`createLinearScale({domain, range, clamp})` → {project, invert, domain, range, nice, ticks}), band.js (`createBandScale` → {position(i), center(i), bandwidth}), sqrt.js (bubble radius). (b) domain/: extent.js (single loop, skips non-finite) and resolve-domain.js (includeZero, explicit bounds with min<max validation, equal-value padding, `include` values such as reference lines, nice). (c) path/: path-builder.js (moveTo/lineTo/bezierCurveTo/arc/close with `precision`; owns fmt). (d) shape/: line.js and area.js (`linePath/areaPath(points, {curve, defined})`), curves/{linear, monotone-x, catmull-rom, step}.js as strategies writing into PathBuilder, arc.js (one direction-aware `arcPath` for pie, donut and gauge arcs). (e) layout/: cartesian, bar (band scale), stack (offsets none|expand|diverging|silhouette|wiggle plus order), pie (padAngle, sort), and chart-specific layouts for radial-bar, candlestick, bullet, win-loss, range-bar and scatter. (f) stats/: linear-regression.js (mean-centred, returns slope/intercept/r2). (g) sample/: lttb.js and min-max.js. (h) frame.js: ChartFrame {width, height, insets} as the single source of viewBox and padding, shared with MiniChartElement.
- Public vs internal: publish only stable primitives from "./math": TAU, extent, resolveDomain, createLinearScale, createBandScale, linePath, areaPath, arcPath, polarToCartesian, createPieLayout (replacing createRadialLayout), createStackLayout, linearRegression, downsample. Make createBulletLayout, createWinLossLayout, createRangeBarLayout, createRadialBarLayout, createCandlestickLayout and createScatterLayout internal, or ship them under "./math/experimental" with @experimental tags, because their outputs encode component presentation ratios. Keep PathBuilder and fmt internal. Migration: in 1.5, add the new names and mark old names (describePieSector, describeArc, createRadialLayout, createSmoothPath, createStepPath) and the root-index re-exports @deprecated as thin wrappers; in 2.0, remove geometry from the root entry.
- Renderer-agnostic chart model for multi-framework and SSR: for each chart, add a pure `computeXxxModel(normalizedData, options)` that returns a plain, serialisable object such as `{viewBox, frame, scales: {x, y} (as domain/range tuples), marks: [{part, kind: 'path'|'rect'|'circle'|'line', attrs}], a11y: {label, valueNow,...}}`. The Web Components only diff this model into the Shadow DOM. React, Vue and Angular wrappers can render the same model as native SVG during SSR, avoiding a hydration flash, and a `renderToSvgString(model)` utility can emit static SVG for emails and OG images. This also gives a clean seam for golden snapshot tests that need no DOM.
- Normalised data model in the data layer, never in geometry: `Series {x?: number[], y: (number|null)[]}`, `OhlcDatum {open, high, low, close, volume?}`, `RangeDatum {min, max, current?}`, `ScatterDatum {x, y, r?}`, `BulletDatum {value, target, ranges, domain?}`. Each is produced by one parser per chart that keeps null in place (gaps) instead of filtering, so stacked series stay index-aligned. Geometry receives only these typed records and exposes a `defined` predicate in the line/area generators.
- Theming hooks in geometry: move spacing and shape constants out of JS literals and into the ChartFrame and layout options: insets, bar gap, measure and target ratios for bullets, tie height for win-loss, inner and outer radius ratios, track width. Components can then map them from CSS custom properties read once per render (for example --mini-chart-inset, --mini-chart-bar-gap, --mini-chart-donut-ratio), so the theming system controls geometry density and not just colour. Clamping and clipping keep every theme inside the viewBox.
- Test strategy for the math module: a per-function matrix (empty, single, equal values, NaN/Infinity, negative, mixed sign, explicit bounds including min>max, out-of-domain values, large n of 1e5-1e6); invariant tests (all coordinates finite and inside the frame plus allowed overflow; the monotone curve stays within the y-range of each segment; stacked layers don't overlap under the diverging offset; arc endpoints match polarToCartesian; band centres equal line x in combo); golden snapshots of path strings at fixed precision; a micro-benchmark that blocks perf regressions; and moving the parseNumericData tests to test/data.test.js. Fix docs/architecture.md to say node:test.

## Findings

### [high] geometry-1: Combo chart line is not aligned with bar centres (band scale vs point scale) (bug)
- Evidence: geometry.js:61 `createLinearScale([0, Math.max(values.length - 1, 1)], [padding, width - padding])` (point scale) vs geometry.js:159-165 slot centres `padding + slotWidth * index + (slotWidth - barWidth) / 2`; mini-combo-chart.js:274-278 uses createBarLayout for bars and createCartesianLayout for the line; mini-combo-chart.js:281-285 crosshair/hover uses line x. Reproduced for n=5: bar centres [11.6,30.8,50,69.2,88.4] vs line x [2,26,50,74,98].
- Detail: Bars sit in n equal slots, while the line spreads its n points from the left padding to the right padding. Only the middle point lines up. The first and last line points land outside their bars, and the hover crosshair also misses the bars. This is visible in every combo chart.
- Rec: Add `createBandScale(count, range, {paddingInner, paddingOuter})` with `center(i)` and `bandwidth`. Add an x mode to createCartesianLayout (`x: 'point' | 'band'`) or let callers pass a shared x scale. The combo chart should place line points on the band centres. Add a test asserting `line.x[i] === bar.x[i] + bar.width/2`.

### [high] geometry-2: Candlestick domain includes every tuple element (volume or timestamp breaks the chart) (bug)
- Evidence: geometry.js:184-185 `const allValues = values.flatMap(v => v); const domain = createDomain(allValues, ...)`; mini-candlestick-chart.js:73-75 accepts any row with `item.length >= 4 && item.slice(0, 4).every(Number.isFinite)`. Reproduced: [[10,12,9,11,5000],...] puts all high/low at y≈27.99-28; [[10,12,9,11,"2024-01-01"]] makes open/high/low/close/bodyY NaN.
- Detail: OHLCV ([o,h,l,c,volume]) is the most common candlestick data shape. The component accepts it, but the layout adds volume to the y domain, so every candle collapses into a flat line at the bottom. A string fifth element turns the whole domain into NaN. Nothing checks that high/low actually bound open/close either.
- Rec: Build the domain from `low` and `high` only, using a loop. Normalise rows into `{open, high, low, close}` records in the data layer (taking only the first 4 elements, or using a named-field accessor). Either fix high/low to max/min of the four values or reject the row. Add tests for OHLCV rows and non-numeric extra fields.

### [high] geometry-3: Smooth curve (uniform Catmull-Rom) overshoots the domain and crosses the zero baseline (bug)
- Evidence: geometry.js:94-97 control points `p1 ± (p2 - p0)/6` (uniform Catmull-Rom, not monotone); used for line/area/stacked/stream/combo (mini-line-chart.js:236, mini-area-chart.js:266/284, mini-stacked-area-chart.js:194, mini-stream-chart.js:193, mini-combo-chart.js:349). Reproduced with [0,0,0,10,10,10], includeZero: control points y=32.333 and -2.333; curve extent y∈[0.07, 29.93] vs plotting band [2,28] and baseline 28.
- Detail: Data that stays flat and then jumps is very common in sparklines (zeros followed by activity). With this data the smooth line dips below the zero baseline and rises above the maximum. In area charts createSmoothAreaPath (geometry.js:111-117) then forms an inverted lobe under the baseline. The overshoot uses up the 2-unit padding and nearly reaches the viewBox edge. If non-uniform x is ever supported, uniform Catmull-Rom can also loop backwards in x.
- Rec: Make 'smooth' a monotone-X cubic (Fritsch–Carlson/Steffen, the same idea as d3.curveMonotoneX). It never overshoots between data points and keeps x monotone. Keep Catmull-Rom as an opt-in `curve: 'catmull-rom'` using centripetal alpha=0.5. Add a test that samples each Bézier segment and checks it stays within [min(y_i), max(y_{i+1})].

### [high] geometry-4: Explicit min/max are not validated and values outside the domain are not clamped (bug)
- Evidence: geometry.js:31-46 createDomain never checks minimum < maximum; geometry.js:62 clamps only the baseline. Components pass attributes straight through: mini-line-chart.js:266-276, mini-area-chart.js:317-328, mini-bar-chart.js:153-164, mini-candlestick-chart.js:231-244. svg.js:20 sets `overflow: visible`. Reproduced: createCartesianLayout([1,2,3],{min:5}) gives domain [5,3] and y=[-24,-11,2]; createBarLayout([2,8],{min:5}) draws bar 0 from y=28 to 54 in a viewBox of height 30.
- Detail: Setting min above the data maximum (or max below the minimum) silently flips the chart upside down and puts geometry outside the viewBox. Because the SVG has overflow:visible, that geometry paints over neighbouring page content. Values outside an explicit domain have no clamp or clip, and an empty array with only min set also produces an inverted domain.
- Rec: Put the domain policy in one place (`resolveDomain`). If min >= max after resolution, fall back to the data extent and warn in dev mode. Add a `clamp` option to the linear scale, and/or have the layout return a plot-area clip rect that components apply. Document the overflow behaviour. Add tests for min>max, only-min-above-data and values outside the domain.

### [high] geometry-5: Stacked layout mishandles negative values and expand mode; component parsing misaligns series (bug)
- Evidence: geometry.js:385-404 keep a single running sum from 0 for every value; geometry.js:394 `offset === "expand" && sum > 0 ? (rawVal / sum) * 100 : rawVal`; geometry.js:382/393 `series[j][i] || 0`; mini-stacked-area-chart.js:78-80 and mini-stream-chart.js:77-79 `series.filter(Number.isFinite)`. Reproduced: [[5,-4],[5,4]] column 1 gives layer0 y 20.57→28 and layer1 28→20.57 (overlap); expand with [-3,2] gives -150%/+100%.
- Detail: (1) A positive layer that follows a negative one is drawn back over the negative region, so the layers overlap. (2) In expand mode, columns whose sum is <= 0 keep raw values while other columns become percentages, so two units share one domain. With mixed signs the percentages also go past ±100. (3) Silhouette centres on the signed sum. (4) The components remove null/non-finite entries from each series, which shifts later values one index to the left. The stack then mixes different time indices, and the missing tail is treated as 0.
- Rec: Add a diverging offset (positives stack up from 0, negatives stack down, like d3.stackOffsetDiverging) and make it the default, or clamp negatives and document it. Compute expand from the sum of absolute values. Replace missing entries with 0 in place (`map`, not `filter`) so indices stay aligned. Add `order` and a 'wiggle' offset for stream graphs. Test coordinates, not just array lengths.

### [high] geometry-6: Data model gap: x is always the index and there is no support for missing values (data-model)
- Evidence: geometry.js:61 and 66-69 (x from index only), geometry.js:410 and 415 (stacked x by index); createSmoothPath/createStepPath (80-144) have no `defined` accessor; data.js:17 `parsed.filter((item) => typeof item === "number" && Number.isFinite(item))` drops nulls.
- Detail: [1,null,3] renders as two evenly spaced points with no break, which misrepresents the series. Line and area charts cannot show unevenly spaced timestamps. The only charts that take real x values are scatter charts. This is the main blocker for 'solid data structures': every chart invents its own input shape, and the geometry cannot express gaps or time.
- Rec: Define a normalised `Series` input (`{ x?: number[], y: (number|null)[] }` or `Datum {x, y}` plus a `defined(d)` predicate). Let createCartesianLayout take an x accessor and an x domain (linear or time). Teach the line/area generators to start a new `M` subpath at gaps (like d3.line().defined). Change the parsers to keep null in place.

### [high] geometry-7: Every geometry export, including chart-specific layouts, is frozen as public API twice (api)
- Evidence: src/index.js:23-44 re-exports all 19 symbols; vite.config.js:33 `math: fromRoot("src/core/geometry.js")` plus package.json exports["./math"]. Chart-specific presentation constants baked into outputs: geometry.js:536 (0.45), 549 (0.75), 596 (0.44), 606-620 (tie h=3, status +2/-4), 702 (min bar height 2), 208 (doji 0.5). No @internal/@experimental tags.
- Detail: Under semver, every fix listed in these findings (domain policy, clamping, curve change, stacking offsets, renamed options) changes the behaviour of a published function. The bullet, win-loss, range-bar, radial-bar and candlestick layouts encode visual ratios that belong to the components, not to a math API. Publishing the same functions from two entry points doubles the surface area to maintain and confuses users about the canonical import path.
- Rec: Make "./math" (or "./geometry") the single home for low-level primitives: scales, domain/extent, line/area/arc generators, pie/stack layouts, regression, downsampling. Move the chart-specific layouts to an internal module or to an explicitly unstable "./math/experimental". In 1.x, keep the root re-exports with `@deprecated` JSDoc; in 2.0, the root entry exports only components and registration.

### [medium] geometry-8: formatNumber is private, so components emit unrounded floats and duplicate the linear path builder (perf)
- Evidence: geometry.js:354-357 (not exported, and no NaN/Infinity guard); hand-built paths without rounding: mini-line-chart.js:240-243 and 404-411, mini-area-chart.js:270-296 and 510-523, mini-stacked-area-chart.js:196-206, mini-stream-chart.js:195-205, mini-combo-chart.js:350, mini-ohlc-chart.js (flatD/d strings); every rect/circle attribute uses String(float). Reproduced: a 1000-point linear path is 38,540 chars (e.g. `2.096096096096096 26.133805753667005`).
- Detail: Geometry has no linear-curve generator, so the 'linear' branch is written by hand four times, each without rounding. Precision is inconsistent: smooth and step paths are rounded to 3 decimals, while linear paths and attributes carry 16-17 significant digits. That makes attribute strings about 2-3x larger, adds DOM and diff cost, and makes snapshot tests unstable. formatNumber outputs 'NaN' and 'Infinity' instead of failing safely.
- Rec: Add an internal `PathBuilder` (moveTo/lineTo/bezierCurveTo/arc/close) with a configurable `precision` (2 decimals is enough for a viewBox about 100 units wide). Export `linePath(points, {curve})` covering linear, monotone, step and catmull-rom, plus `areaPath`. Route every numeric attribute through one exported `fmt()`.

### [medium] geometry-9: Math.min/Math.max with spread arguments crash on large arrays (bug)
- Evidence: geometry.js:32-33 (createDomain), 185 (via createDomain), 372, 434, 504-505, 685-686, 778-781. Reproduced: createDomain on 130,000 values throws `RangeError: Maximum call stack size exceeded` (120k works).
- Detail: Every layout that computes an extent can throw on large inputs, for example when users feed raw telemetry into a sparkline. The exact limit depends on the engine and is lower on some mobile browsers. For a library meant to be stable this is a crash rather than a slowdown.
- Rec: Add an `extent(values, accessor?)` helper that uses a single loop and skips non-finite values. Use it everywhere. Add a test with 1e6 values.

### [medium] geometry-10: No downsampling for large series (perf)
- Evidence: createCartesianLayout maps every value to a point (geometry.js:66-69); createSmoothPath and createStepPath emit one command per point (88-100, 131-142); line/area pointer handling scans every point linearly (mini-line-chart.js:179-185).
- Detail: A 1000-point series in a plot 96 units wide, rendered about 100 px wide, means roughly 10 path commands per CSS pixel. The extra commands add no visual detail but cost string building, parsing and paint time, and they also slow the CSS `d` transitions.
- Rec: Add `downsample(points, threshold, {method: 'lttb' | 'min-max'})` under sample/. Expose it as a layout option (`maxPoints`, defaulting to about 2× the plot width in px or a fixed 300). Keep an index map so hover reports the original values. Use invert() plus binary search for hover.

### [medium] geometry-11: Arc generators ignore direction and start angle for full circles (bug)
- Evidence: geometry.js:266 and 332 `Math.abs(endAngle - startAngle)`; sweep flag hard-coded to 1 at 303, 314 and 349; full-circle branches 271-293 and 335-340 always start at (cx, cy-r). mini-radial-bar-chart.js:236-240 accepts a negative `sweep` attribute. Reproduced: describeArc(50,50,40,0,-π/2) gives `M 90 50 A 40 40 0 0 1 50 10` (drawn on the mirrored circle); describeArc(50,50,40,0,2π) starts at `M 50 10`.
- Detail: Counter-clockwise arcs (endAngle < startAngle) are drawn on the wrong circle and bulge outwards. A full circle always starts at 12 o'clock whatever startAngle is, so stroke-dasharray progress animations start in the wrong place unless startAngle happens to be -π/2. Sweeps larger than 2π are silently drawn as a single circle. There are also two separate full-circle code paths with opposite winding.
- Rec: Replace describePieSector and describeArc with one `arcPath({cx, cy, outerRadius, innerRadius, startAngle, endAngle, padAngle?, cornerRadius?})`. Set sweepFlag = end > start ? 1 : 0 and draw a full circle as two half-arcs starting from startAngle. Keep the old names as deprecated wrappers.

### [medium] geometry-12: A slice of nearly 100% disappears because of the rounding/EPSILON mismatch (bug)
- Evidence: geometry.js:5 `EPSILON = 0.000001`, 269 full-circle threshold `sweep >= TAU - EPSILON`, 355 rounding to 3 decimals. Reproduced: createRadialLayout([1e6,1]) slice 0 gives `M 50 50 L 50 2 A 48 48 0 1 1 50 2 Z`.
- Detail: When the remaining slices are tiny, the dominant slice's sweep falls just under the full-circle threshold. After rounding, its arc start and end points are identical, and the SVG spec says such an arc segment is omitted, so the largest slice renders as nothing. This happens with ratios of roughly 1:60,000 at radius 48.
- Rec: Treat a slice as a full circle when its rounded endpoints coincide: set the threshold from precision and radius (sweep > TAU - 10^-precision / r). Alternatively, split any arc wider than π into two arcs. Add tests for near-full and near-empty slices.

### [medium] geometry-13: Linear regression is numerically unstable and its line is unbounded (bug)
- Evidence: geometry.js:803-833 naive `n*sumXX - sumX*sumX` with a fixed 1e-9 tolerance; trend endpoints at domainX ends with no clamp to domainY (821-831). Reproduced: 60 points with ms timestamps 1 s apart give trendLine null; 1 min apart gives about 0.01 units of error.
- Detail: Epoch timestamps are the most common x values for scatter sparklines. Catastrophic cancellation makes the trend line disappear silently or come out slightly wrong. The fitted line can also extend outside the y domain or explicit bounds, and with overflow:visible it paints outside the chart. Slope, intercept and r² are not exposed to consumers.
- Rec: Move the fit to `stats/linearRegression(points)` using a mean-centred two-pass calculation (or Welford) that returns {slope, intercept, r2}. Clip the line to the plot rect with Liang–Barsky against the domain. Test with an x offset of 1.7e12.

### [medium] geometry-14: Bullet layout hard-codes a 0–100 domain and ignores the zero baseline for negative values (bug)
- Evidence: geometry.js:504-505 `Math.min(0, ...allPoints)` / `Math.max(100, ...allPoints)`; geometry.js:539-543 measure always starts at `padding` (= min). Reproduced: createBulletLayout([0.7,0.8]) gives max 100 and a measure width of 0.658 out of 94.
- Detail: Ratio data (0–1) or small values produce an invisible measure bar unless the user sets max. For negative values, Stephen Few's bullet graph draws the measure from zero, but here it always starts at the domain minimum.
- Rec: Derive the auto domain from the data with a nice() round-up, and keep 0–100 only when explicitly requested. Draw the measure from clamp(0, min, max) to the value. Return the scale so the component can position labels.

### [medium] geometry-15: Each layout handles degenerate domains and single points differently (architecture)
- Evidence: createDomain ±10% or ±1 (geometry.js:40-43); scatter [v, v+1] (784-786); bullet min+1 (507); range-bar has no handling and relies on createLinearScale `|| 1` (17, 685-695); single point centred in cartesian (67) and stacked (415) but placed at the corner in scatter (reproduced {x:4, y:26}).
- Detail: The same input (all values equal, or one value) is drawn centred in one chart, pinned to the bottom in another and placed in a corner in a third. The inconsistency makes behaviour hard to document and test, and every new chart reinvents the rule.
- Rec: Use one `resolveDomain(values, {includeZero, min, max, nice, padRatio})` everywhere, with a documented equal-value policy (symmetric padding) and a single-point policy (centred).

### [medium] geometry-16: Layout constants are copied between geometry and the components (architecture)
- Evidence: Reference line `(this.chartHeight - 2) - (...) * (this.chartHeight - 4)` repeats padding=2 (mini-line-chart.js:298, mini-area-chart.js:350 vs geometry.js:57); win-loss baseline x1=2/x2=width-2 vs layout padding 3 (mini-win-loss-chart.js:197-200, 197); centre 50,50 and radii 48/46/44/40 (mini-pie-chart.js:178,196; mini-half-pie-chart.js:174,191; mini-radial-bar-chart.js:246-247; mini-gauge-chart.js:349,366); progress chart hard-codes `M 10 50 A 40 40 0 0 1 90 50` (mini-progress-chart.js:144,149); gauge re-implements an angle scale (mini-gauge-chart.js:362-363) and does not clamp zone `upTo` to [min,max] (273-274), so zones past max wrap beyond the semicircle; viewBox 100×30 is defined both in geometry defaults and in mini-chart-element.js:24-31.
- Detail: Changing any padding default silently breaks reference lines and baselines. Components cannot be themed for spacing, because insets are numbers hidden in JS rather than tokens. Gauge zones that extend beyond max render as arcs past 180°.
- Rec: Add a `ChartFrame` {width, height, insets:{top,right,bottom,left}} as the single source, shared by layouts and components. Have layouts return their scales so components never re-derive projections. Draw the gauge and progress arcs with arcPath plus a clamped angle scale.

### [medium] geometry-17: Reference line is recomputed by hand and can render outside the chart (bug)
- Evidence: mini-line-chart.js:295-304 and mini-area-chart.js:347-356 compute refY manually with no clamp; geometry.js:64-71 returns `domain` but not its scales; svg.js:20 `overflow: visible`.
- Detail: A reference value outside the data domain draws outside the element box, on top of surrounding content. Users usually expect the reference value to be included in the domain so it stays visible.
- Rec: Have createCartesianLayout return {xScale, yScale} with project and invert. Add a domain option `include: number[]` (for example [referenceValue]) and clamp or hide lines outside the plot rect.

### [medium] geometry-18: Public functions do not guard inputs (NaN, gapRatio, zero denominators) (bug)
- Evidence: createDomain([1,NaN,3]) gives [NaN,NaN] and `M 2 NaN C 10 NaN…` (reproduced); createRadialLayout NaN gives total NaN (geometry.js:239-240); createRadialBarLayout with maxDomain=0 and value 0 gives 0/0 = NaN angle (443); gapRatio not clamped in createBarLayout (160) or createCandlestickLayout (190), so gapRatio 1.5 gives width -24 (reproduced), while win-loss (599) and range-bar (692) do clamp; win-loss status mode `innerHeight - 4` goes negative when height < 10 (612); scatter accepts negative `r` (762, 767).
- Detail: The components currently pre-filter their data, but anyone calling the published "./math" API can easily produce NaN paths or negative rect sizes. NaN in an SVG attribute makes the browser log errors and draw nothing.
- Rec: Add one options-resolution step per layout that clamps ratios, sizes and radii and rejects non-positive denominators. Have extent() skip non-finite values. Document the behaviour for invalid input and test it.

### [medium] geometry-19: Function signatures, option names and output shapes are inconsistent (api)
- Evidence: Positional signatures: describePieSector (geometry.js:265, 6 args), describeArc (331), polarToCartesian (224), against `(data, options)` everywhere else. Domain option names: min/max, minX/maxX/minY/maxY (751), maxDomain (432), data.min/max (496-497). Keys: baseline vs baselineY (590, 633). endAngle in radial-bar output means 'value angle' (450). Defaults: padding 2/3/4, gapRatio 0.2/0.25, height 30 vs 100 (432), startAngle -π/2 (238) vs 0 (432). Unused width/height options (432). Candlestick `open/high/low/close` are pixel y values (200-205) while bullet `value/target` are data values (563-564).
- Detail: Each function has to be learned separately, typed wrappers for React, Vue and Angular cannot share option types, and pixel and data units are easy to mix up. The unused options suggest an API surface that doesn't actually exist.
- Rec: Standardise on `fn(data, {frame, domain, ...})` returning `{domain, scales, items}`. Put pixel geometry under named sub-objects (`items[i].rect`, `items[i].wick`) and keep the data fields raw. Replace the positional radial functions with options objects. Remove dead options.

### [medium] geometry-20: Geometry parses polymorphic input; scatter tuple bug and unscaled bubble radius (data-model)
- Evidence: Input parsing inside layouts: createBulletLayout (geometry.js:484-498), createRangeBarLayout (661-682), createScatterLayout (758-773); bullet input is parsed again in the component (mini-bullet-chart.js merges into an object before calling the layout).
