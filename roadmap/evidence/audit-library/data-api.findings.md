# data-api

## Summary
The data contract is the weakest part of the library, and it currently blocks the stability and multi-framework goals. Each of the 17 charts accepts its own ad-hoc shape: flat numbers, positional tuples (gauge [value,min,max], bullet [value,target,...ranges]), datum-major tuples (OHLC, range, scatter), series-major matrices (stacked, stream) or bespoke objects (combo {bar,line}). There is no shared type, normalizer, accessor, label/x/timestamp field, Date support or null-gap semantics. Parsing runs on the JSON attribute. The base parseNumericData drops invalid values silently, which shifts indices, so event indices and series alignment become wrong. Five charts reimplement parsing, two of them (range-bar, scatter) with no filtering at all. I verified in Node with a fake DOM that a single null datum throws a TypeError in range-bar, scatter and bullet. A bare number given to bullet renders 0 and ignores the target attribute. 9 of 17 charts override `get data()` without a setter, so `el.data = ...` throws 'which has only a getter'. The Angular directives make exactly that assignment for every chart, and React 19 property semantics would hit the same path (and double-encode the pre-stringified value on the other 8). Options are 41 distinct string attributes parsed with parseFloat(getAttribute(x)||'') or hasAttribute, with no enum validation and no diagnostics (zero console warnings in src). Their names and meanings are inconsistent: gap/bar-gap; radius meaning rx, CSS px or ratio; gradient on by default in one chart and off in four. Six attributes are observed but never read, and seven are read only on first render. Events are inconsistent too: five different names (one, slice-select, is listened to by the wrappers but never dispatched), different index keys, internal shadow nodes leaked in `detail`, and colors reported from the palette instead of the themed value. Labels and value text have no number formatter or locale. The per-component docs disagree with the code on data shapes (combo, range-bar, gauge, candlestick), parts and CSS variables, so the public contract today is effectively undefined. The fix is a schema-driven core: typed per-chart data schemas plus a normalizer with diagnostics, property-first options with attribute converters, one event table, and a deprecation layer. Wrappers, docs and a custom-elements manifest should be generated from that same schema.

## Proposals
- P1 - Normalized data model (src/core/model/*.ts, exported as 'sparkline-mini-charts/types'). Core types: `type Gap = null | undefined; type NumberLike = number | Gap;` `interface Datum<V = number> { value: V | null; x?: number | Date | string; label?: string; color?: string; meta?: unknown }` `interface Series<D = Datum> { id?: string; name?: string; color?: string; data: readonly D[] }` `type Accessor<T, R> = keyof T | ((d: T, i: number) => R)` `interface Binding<T> { data: readonly T[]; x?: Accessor<T, number | Date | string>; y?: Accessor<T, NumberLike>; label?: Accessor<T, string>; color?: Accessor<T, string> }`. Per-chart input schemas, each accepting a legacy shorthand plus the canonical form: `LineInput = readonly NumberLike[] | readonly Datum[] | Binding<any>` (line, area, bar, win-loss, pie, half-pie); `MultiSeriesInput = readonly (readonly NumberLike[])[] | readonly Series[]`, always series-major, with optional shared `categories` (stacked, stream, radial-bar, combo); `ComboInput = { series: Series<Datum & { type: 'bar' | 'line' | 'area' }>[] }`, with a legacy `{bar, line}[]` adapter; `OhlcDatum = { open; high; low; close; volume?; x? }` with a legacy `[o,h,l,c]` tuple; `RangeDatum = { low; high; value?; x?; label? }`, with legacy `[lo,hi,cur]` and `{min,max,current}` (current also aliased as value); `ScatterDatum = { x; y; size?; label?; color? }`; `ScalarInput = number | { value; min?; max? }` (progress, gauge), with legacy `[v,min,max]`; `BulletInput = number | { value; target?; ranges?: number[]; min?; max? }`, with legacy `[v,t,...r]`; `WinLossDatum = -1 | 0 | 1 | null | { outcome: 'win' | 'loss' | 'tie'; label? }`. A single `normalize(kind, input, {accessors, gaps})` returns `{ series: { id, name, color, values: Float64Array /* NaN = gap */, x: Float64Array | null, labels: string[] | null, sourceIndex: Int32Array }[], domain: { x: [n, n], y: [n, n] }, issues: DataIssue[] }`. It never throws, it is pure and SSR-safe, and the geometry layer consumes only this shape (path builders break on NaN unless gaps='connect'). Unit-test it with a shared fixture corpus (valid, null, NaN, strings, extra tuple fields, ragged series, Dates, 100k points).
- P2 - Property-first API with optional attribute reflection. Add a zero-dependency `defineOptions(Class, schema)` (about 1-2 KB) in core that generates, for each option, a property accessor backed by private state. Each option has a `fromAttribute` converter, an optional `reflect: true` (only for short primitives such as curve or interactive), and a static `observedAttributes` derived from the schema, so drift between observed and read attributes becomes impossible. Data rules: `el.data = value` stores the reference (no stringify) and normalizes lazily on render. The `data` attribute stays as an HTML/SSR convenience and is parsed only on the attribute path, with documented precedence (last write wins). Updates work by assigning a new array; in-place mutation needs `el.requestUpdate()`. Base lifecycle: connectedCallback runs `upgradeProperty()` for every schema key (so pre-definition assignments are handled), attaches listeners idempotently, then `requestRender()`. disconnectedCallback cancels timers. Rendering reads one frozen `ResolvedOptions` object, never `getAttribute`. Expose `label` and `locale` as properties too. Wrappers then pass objects as properties directly: React 19 passes them through when `name in el`, React 18 uses a ref effect, Vue uses `.prop` modifiers or `h(tag, {'.data': value})`, Angular uses property bindings. This removes all JSON stringification from the wrappers.
- P3 - Per-chart options schema with defaults, validation and dev warnings. One source file per chart, e.g. `export const lineSchema = { data: Data(LineInput), min: Num(), max: Num(), curve: Enum(['linear','smooth','step','step-before','step-after'], 'linear'), markers: Enum(['none','last','first-last','min-max','all'], 'last'), referenceLines: Json(ReferenceLine[]), colorMode: Enum(['fixed','trend'], 'fixed'), gaps: Enum(['drop','break','connect','zero'], 'drop'), interactive: Bool(), animate: Bool(true), locale: Str(), valueFormat: Json(IntlNumberFormatOptions), label: Str() }`. Converters: Num (finite or undefined, optional clamp range), Bool (presence = true; 'false' accepted with a deprecation warning), Enum (unknown value → default + warning), Json (parse + structural validator), ColorList (tokenizer that respects parentheses), Angle (degrees). Development mode is detected via `globalThis.SPARKLINE_DEV ?? (typeof process !== 'undefined' && process.env.NODE_ENV !== 'production')` and is dead-code-eliminable. `warnOnce(tag, key, reason, value)` warns once per element and key, and data and option problems are also dispatched as `sparkline-data-issue` (in production too, so apps can log them). The same schema generates React prop interfaces, Vue props, Angular `input()`s, `custom-elements.json` (CEM, for IDE autocompletion and Storybook) and the docs tables, with a CI check for drift.
- P4 - Consistent attribute naming scheme, kebab-case attributes mirrored by camelCase properties. Scale: `min`/`max` for the value axis everywhere (implement them in radial-bar, combo and stacked); `x-min`/`x-max`/`y-min`/`y-max` (aliases: min-x etc.); `include-zero`; `independent-scales` (replaces shared-domain='false'). Geometry: `gap` (replaces bar-gap); `corner-radius` (bar, range-bar, win-loss; always viewBox units); `point-size` (replaces point-radius); `hole` 0–0.9 plus a presence `donut` (replaces inner-radius); `start-angle`/`sweep-angle` (degrees, available on pie, half-pie and radial); `pad-angle` (implement it); `stroke-width`/`wick-width` as numeric options mapped to internal CSS variables. Color: `color-mode="fixed|trend|sign|series"` (replaces trend-color, and makes bar positive/negative explicit); `gradient` presence plus a `gradientStops` property; win/loss/tie colors only as CSS tokens (drop the dead attributes). Reference: `referenceLines`/`thresholds` property (replaces reference-value), plus `reference-value` kept as a shorthand; bullet keeps `target`/`ranges`; gauge `bands=[{to, color, label}]` (alias: zones/upTo). Markers: `markers` (replaces points), `needle="triangle|line"`. Animation: `animate` (default on, presence `no-animate` to disable), `animation-duration`, always respecting prefers-reduced-motion. Interaction: `interactive`, `selectable`. Value display: `show-value`, `unit` (generalized to gauge), `locale`, `value-format`. Rule: every default-true behaviour gets a negative presence attribute (`solid-bullish`, `square-caps`, `no-gradient`), so booleans are always presence = true.
- P5 - Consistent event model. Event names: `sparkline-hover`, `sparkline-leave`, `sparkline-select` (click / Enter / Space), `sparkline-focus` (keyboard roving index), `sparkline-threshold` (edge-triggered on band, zone or target crossing and on reaching max; replaces zone-change and progress-complete), `sparkline-data-issue`, and `sparkline-render` (after paint, with the resolved domain, for tests and SSR hydration). Every event uses bubbles + composed, and none is cancelable except select. One detail type: `interface SparklinePointDetail<D = unknown> { chart: ChartKind; index: number; sourceIndex: number; seriesIndex: number; seriesId?: string; datum: D; value: number | null; values?: Record<string, number> /* ohlc, combo, range */; formattedValue: string; label?: string; x?: number | Date | string; color: string /* computed */; percentage?: number; position: { x: number; y: number } /* CSS px relative to host */; pointerType: 'mouse' | 'touch' | 'pen' | 'keyboard' }` and `interface SparklineThresholdDetail { kind: 'band' | 'target' | 'complete'; value: number; from: number | null; to: number | null; band?: { to: number; color: string; label?: string } }`. Rules: hover fires only when (seriesIndex, index) changes; never expose internal nodes; read colors via getComputedStyle; ship `declare global { interface HTMLElementTagNameMap {...}; interface HTMLElementEventMap { 'sparkline-hover': CustomEvent<SparklinePointDetail> ... } }`; generate the wrapper outputs (onSparklineHover, @sparkline-hover, (sparklineHover)) from the same event table.
- P6 - Versioned migration path. v1.4.x patch: restore the `data` setter on all 17 charts; fix the null crashes, bullet scalar handling, the radial stale rings, the listener re-attach and trend-color's inline-style mutation; fix the docs for the combo, range-bar and gauge shapes. These are pure bug fixes with no API change. v1.5 (minor, additive): introduce `normalize()` plus the schemas behind the existing shapes; accept the new canonical shapes alongside the old ones; add properties for all options and `upgradeProperty`; add the new attribute names with old-name aliases handled by a base `static deprecated = { 'bar-gap': { to: 'gap', since: '1.5', removeIn: '2.0' }, 'inner-radius': { to: 'hole' }, 'trend-color': { to: 'color-mode', map: { auto: 'trend' } }, ... }` table that maps the value and calls warnOnce; dispatch both legacy and new events (zone-change and sparkline-threshold); add a `gaps` option defaulting to 'drop' (current behaviour) with a warning recommending 'break'; publish CEM and generated docs. v1.6: flip wrappers to property passing; add an `element` getter on the detail that warns when read. v2.0 (major): remove the legacy names, positional tuples (bullet [v,t,...r], gauge [v,min,max]), the `{bar,line}` combo shape, the legacy events and `element`; change the `gaps` default to 'break'; replace the exported `parseNumericData` with `normalize`/`toSeries` (keep `parseNumericData` in a `sparkline-mini-charts/compat` entry that also installs the alias and event re-dispatch shims for apps that need more time). Ship a MIGRATION.md with an old→new table generated from the deprecation map, plus a small codemod (regex for HTML attributes, jscodeshift for JSX/Vue props).
- P7 - Contract test suite that locks the API. Per chart: (a) parity between attribute and property for each fixture; (b) the fixture corpus from P1 never throws, renders deterministically and produces the expected `issues`; (c) every schema option changes the output (catches dead attributes) and stays reactive after the first render (catches createDOM-only reads); (d) event detail snapshots against the shared type; (e) connect → disconnect → connect keeps interaction working; (f) when the data length shrinks, no stale nodes stay visible; (g) generated docs, wrapper types and CEM match the schema (CI diff). Extend the existing fake DOM in test/components.test.js or move to happy-dom so that pointer events can be dispatched.

## Findings

### [critical] data-api-1: 9 of 17 charts have a getter-only `data` property: `el.data = ...` throws, and the Angular directives do exactly that (api)
- Evidence: Base accessor pair: src/core/mini-chart-element.js:44-51. Getter-only overrides: mini-bullet-chart.js:69, mini-candlestick-chart.js:69, mini-combo-chart.js:79, mini-ohlc-chart.js:61, mini-radial-bar-chart.js:78, mini-range-bar-chart.js:68, mini-scatter-chart.js:70, mini-stacked-area-chart.js:74, mini-stream-chart.js:73. Angular `el.data = d`: src/angular/mini-chart.directive.ts:235,271,390,522,564,604,645,732,775,847. Checked in Node: Object.getOwnPropertyDescriptor shows set=undefined; assignment gives 'TypeError: Cannot set property data of #<MiniCandlestickChart> which has only a getter'.
- Detail: In a class, an accessor defined with only `get` shadows the inherited get/set pair, so the setter disappears. ES modules and TypeScript run in strict mode, so assignment throws instead of being ignored. Vanilla property usage is broken for bullet, candlestick, combo, ohlc, radial-bar, range-bar, scatter, stacked-area and stream, and so is the Angular integration for those charts (the `effect` throws). React 19 assigns custom-element props as properties when `name in element`. The React wrapper pre-stringifies `data` (src/react/index.ts:233), so on these 9 charts it would hit the same throw, and on the other 8 the base setter double-encodes the string. I verified the double-encoding in Node: `el.data = "[10,25,40]"` stores `"\"[10,25,40]\""` and parses back to `[]`, an empty chart. README.md:37 claims attributes and properties are synchronized.
- Rec: Hotfix in 1.4.x: move parsing into an overridable `parseData(raw)` hook on the base class and stop overriding the `data` accessor in subclasses. Make the setter accept already-parsed values (store the reference, do not stringify) and keep strings on the attribute path. Add a contract test that, for every registered chart, `'set' in descriptor` holds and `el.data = fixture` renders the same as `setAttribute('data', JSON.stringify(fixture))`.

### [critical] data-api-2: A null datum crashes range-bar, scatter and bullet during render (bug)
- Evidence: src/components/mini-range-bar-chart.js:72 returns the parsed array unfiltered, then :80 `d.min` on null. src/components/mini-scatter-chart.js:76 unfiltered, then :82 `d.y ?? d.x`. src/components/mini-bullet-chart.js:82 `data.value` when data is null. Checked with a fake DOM: 'TypeError: Cannot read properties of null (reading 'min' / 'y' / 'value')'.
- Detail: null is the natural encoding of a missing sample, and it is what JSON.stringify produces for NaN or undefined array entries. These three charts compute the default aria label from unvalidated input, so one null throws inside the microtask render. The chart is left blank or stale and an uncaught error reaches the page. The geometry functions would have handled the input; the crash is in the component's label code.
- Rec: Route every chart through one normalizer that never throws and returns `{model, issues}`. Compute labels from the normalized model, never from raw input. Add fixture tests with `null`, `[null]`, `[[1,2],null]`, `"abc"` and `{}` for every chart.

### [high] data-api-3: Bullet: a scalar `data` renders 0 and ignores the target/min/max/ranges attributes (bug)
- Evidence: src/components/mini-bullet-chart.js:69-78: the getter returns any JSON value. :229-255 merges attributes only for arrays and objects, so a number falls through to createBulletLayout(42), which yields value 0 (src/core/geometry.js:484-498). Checked: data='42' target='80' gives aria-valuenow='0' and target x1=3 (the minimum).
- Detail: The most natural single-KPI input (data='42', or `el.data = 42` through JSON) is silently replaced by 0. The documented override attributes are dropped because the merge branch only handles arrays and objects. Strings like '"abc"' also render 0 with no warning.
- Rec: In the bullet schema, accept `number | [value, target?, ...ranges] | {value, target?, ranges?, min?, max?}` and normalize all three to one `BulletModel` before merging attributes. Emit a dev warning or data-issue event for anything else.

### [high] data-api-4: Invalid values are dropped silently, which shifts indices and misaligns series; some charts invent values instead (data-model)
- Evidence: src/core/data.js:17 filters instead of preserving holes. src/components/mini-stacked-area-chart.js:78-80 and mini-stream-chart.js:77-79 filter each series (checked: [[1,2,3,4],[10,null,30,40]] becomes [[1,2,3,4],[10,30,40]]), then src/core/geometry.js:382,393 pad with 0. src/core/geometry.js:760-767: scatter bad y becomes 0, bad x becomes the index. geometry.js:663-673: range-bar non-finite becomes 0. mini-combo-chart.js:83-89 drops the whole datum. mini-line-chart.js:201-205 reports `index` from the filtered array.
- Detail: No chart supports gaps. For single series, removing values compresses the x positions, so the visual position and `sparkline-hover.detail.index` no longer match the caller's array. For stacked and stream, every value after the hole slides into the previous time slot, which is silent data corruption. Scatter and range-bar render points or bars that are not in the data. Nothing is reported: there is no console warning anywhere in src/ and no error event. JSON.stringify inside the setter turns NaN and Infinity into null as well, so live feeds lose samples without any trace.
- Rec: Make `null`/`undefined`/`NaN` an explicit gap in the normalized model: Float64Array values with NaN, plus `sourceIndex` mapping. Add a `gaps: 'break' | 'connect' | 'zero'` option; keep 'drop' only as a deprecated 1.x default with a warning. Path builders should restart with `M` after a gap. Events should report `sourceIndex`. Emit `sparkline-data-issue` with `{index, reason, value}` and warn once in development.

### [high] data-api-5: Candlestick/OHLC: extra tuple fields corrupt the price scale, and OHLC invariants are not checked (bug)
- Evidence: src/components/mini-candlestick-chart.js:74 and mini-ohlc-chart.js:66 accept `item.length >= 4` and check only the first 4 fields. src/core/geometry.js:184 `values.flatMap(v => v)` puts every element into the domain. Checked: [[10,12,9,11,50000],...] collapses every candle to a flat line at y=28; [[10,12,9,11,'2024-01-01'],...] produces all-NaN coordinates.
- Detail: The OHLCV `[o,h,l,c,volume]` shape and timestamped tuples are the most common financial feeds. The volume dominates the domain, and a string poisons Math.min/max. There is no check that high ≥ max(open,close) and low ≤ min(open,close), so inconsistent rows render as broken wicks. There is also no x/timestamp field, so time gaps are invisible.
- Rec: Define `OhlcDatum = {open, high, low, close, volume?, x?: number | Date | string}` and keep `[o,h,l,c]` tuples as an accepted input. Build the domain only from o/h/l/c, validate the invariants (warn and repair by expanding high/low), and support volume as an optional secondary encoding later.

### [high] data-api-6: No unified typed data contract: 17 bespoke shapes, two conflicting 2D orientations, positional tuples, and no labels, x values or dates (data-model)
- Evidence: Positional tuples: mini-gauge-chart.js:301-303 ([value,min,max]); mini-bullet-chart.js:229-244 ([value,target,...ranges]). Series-major: mini-stacked-area-chart.js:74-84. Datum-major: mini-candlestick-chart.js:69-79, mini-range-bar-chart.js:68-76, mini-scatter-chart.js:70-78. Bespoke object: mini-combo-chart.js:79-93 ({bar,line}). Per-datum color only in mini-radial-bar-chart.js:82-84. Parsers duplicated: candlestick:69-79 = ohlc:61-71; stacked:74-84 = stream:73-83. Checked: Date becomes an ISO string and is dropped.
- Detail: There is no Datum/Series abstraction, so features cannot be added once for all charts: tooltips with category labels, timestamps, per-datum colors, series names, accessors for user objects. Users must reshape their domain objects into each chart's idiosyncratic shape and JSON-encode them. The x axis is always the array index except in scatter, so irregular time series are drawn evenly spaced. TypeScript users get `data?: any` (src/react/index.ts:41).
- Rec: Introduce `src/core/model/`: shared `Datum`, `Series` and `Accessor` types; one schema per chart; and `normalize(kind, input, accessors)` → `{series: NormalizedSeries[], domain, issues}`. All charts render only from the normalized model. Publish the types from a `./types` entry and use them in wrappers and the d.ts output. See proposals.

### [high] data-api-7: Public docs and wrapper types contradict the code on data shapes and enum values (docs)
- Evidence: docs/components/mini-combo-chart.md:6-23 ([{type,values}]) vs mini-combo-chart.js:79-93 ({bar,line}). docs/components/mini-range-bar-chart.md:7 ({min,max,value?}) vs geometry.js:674 (`current`; checked: marker hidden). docs/components/mini-candlestick-chart.md:6 ('exactly 4') vs mini-candlestick-chart.js:74. docs/components/mini-gauge-chart.md:6-8 omits the positional min/max. docs/components/mini-win-loss-chart.md:18 'binary' vs mini-win-loss-chart.js:185; src/react/index.ts:172 'uptime'. src/react/index.ts:52 points 'ends' (not implemented) and no 'min-max'. docs/components/mini-bar-chart.md:19 has a leftover draft sentence.
- Detail: A user following the docs gets an empty combo chart and range bars with no markers. Hand-written docs, hand-written React/Vue/Angular types and the components have drifted independently, so there is no single source of truth for the API.
- Rec: Generate the attribute/property/event/part/CSS-variable tables, wrapper prop types and custom-elements.json from the per-chart schema (see proposals). Add a CI check that fails when docs or wrapper types are out of sync with the schema.

### [high] data-api-8: Six observed attributes are never read and seven are read only on first render (api)
- Evidence: Dead: mini-bar-chart.js:18 `baseline`; mini-pie-chart.js:19 `pad-angle`; mini-radial-bar-chart.js:27 `min`; mini-win-loss-chart.js:24-26 `win-color`/`loss-color`/`tie-color`. Read only in #createDOM: mini-candlestick-chart.js:102-103, mini-ohlc-chart.js:94, mini-gauge-chart.js:172, mini-radial-bar-chart.js:112, mini-range-bar-chart.js:98, mini-win-loss-chart.js:86. Advertised by wrappers: src/react/index.ts:64,95,110,173-178; src/angular/mini-chart.directive.ts:134,154.
- Detail: Changing these attributes triggers a re-render that does nothing, so a framework binding such as `[needleType]` or `roundCaps={false}` looks broken. The wrappers and docs present the dead attributes as features, which undermines trust in the whole API.
- Rec: For each attribute either implement it reactively (resolve options on every render, not in #createDOM) or remove it with a deprecation warning. Enforce this with a schema-driven test: every schema option must change the rendered output, and every observed attribute must exist in the schema.

### [high] data-api-9: Boolean and gradient attributes follow three conventions, so `false` cannot be expressed through the React wrapper (api)
- Evidence: Presence only: `interactive` everywhere (e.g. mini-line-chart.js:170), so interactive='false' still enables it. 'false' string turns it off: mini-scatter-chart.js:200. Default true: mini-candlestick-chart.js:102, mini-radial-bar-chart.js:112, mini-combo-chart.js:264, mini-area-chart.js:380-381 (gradient on by default) vs mini-bullet-chart.js:194-197, mini-gauge-chart.js:244-249, mini-progress-chart.js:206-209 (gradient off by default). The React wrapper drops false booleans: src/react/index.ts:258-260.
- Detail: Because the React wrapper emits nothing for `false` and the components treat a missing attribute as true for hollow-bullish, round-caps, shared-domain and area gradient, React users cannot disable those features (`hollowBullish={false}` stays hollow). The same attribute name, `gradient`, means opposite defaults in different charts. The comma-split fallback for gradient colors (e.g. mini-area-chart.js:392-393) breaks colors that contain commas, such as `rgb(1,2,3)`.
- Rec: Make every boolean presence-based and false by default. Invert the default-true ones into negative names (`solid-bullish`, `square-caps`, `independent-scales`, `no-gradient` or `fill="solid"`) with deprecation aliases. Make `gradient` presence-based everywhere and move color stops to a `gradientStops` property, with a CSS-color-aware parser for the attribute form.

### [high] data-api-10: Events are inconsistent: five names, one never dispatched, different detail keys, leaked shadow nodes, wrong colors, repeated firing (api)
- Evidence: Names: sparkline-hover/leave everywhere; sparkline-select mini-candlestick-chart.js:172; zone-change mini-gauge-chart.js:384; progress-complete mini-progress-chart.js:303; slice-select listened to in src/vue/index.ts:41,52, src/angular/mini-chart.directive.ts:68, src/react/index.ts:35 but never dispatched. Keys: trackIndex mini-radial-bar-chart.js:163; layerIndex mini-stacked-area-chart.js:161; barValue/lineValue mini-combo-chart.js:210-211; raw `data` in mini-range-bar-chart.js:148, mini-scatter-chart.js:150, mini-bullet-chart.js:167. `element` leaked in 10 charts (e.g. mini-bar-chart.js:113). Palette color instead of themed color: mini-pie-chart.js:130, mini-half-pie-chart.js:128, mini-stacked-area-chart.js:156, mini-stream-chart.js:155. progress-complete on every render: mini-progress-chart.js:302-308 (checked: 3 events after 3 renders). Hover repeats on pointermove with an unchanged index: mini-line-chart.js:169-205, mini-gauge-chart.js:205-219, mini-progress-chart.js:168-181. React handlers dropped: src/react/index.ts:224-227.
- Detail: Consumers cannot write one generic tooltip handler. Exposing internal SVG nodes makes the shadow DOM structure part of the public API, so any refactor becomes a breaking change. Colors in events are wrong once themed through `--mini-chart-color-N`. 'Complete' and 'zone' notifications are not edge-triggered. The typed React props `onSparklineHover` etc. are destructured and never attached. There are no `HTMLElementEventMap` typings.
- Rec: Adopt one event table, shared by components and generated wrappers: `sparkline-hover`, `sparkline-leave`, `sparkline-select`, `sparkline-threshold` (replacing zone-change and progress-complete, edge-triggered with `{kind, from, to}`), and `sparkline-data-issue`. Use one `SparklinePointDetail` shape (see proposals). Read colors via getComputedStyle, fire only when the index changes, provide keyboard parity, and keep `element` out of the detail. Re-dispatch the legacy names during the deprecation window.

### [high] data-api-11: Interaction stops working after an element is detached and re-attached (bug)
- Evidence: src/core/mini-chart-element.js:57-59 disconnectedCallback → cleanup(). mini-line-chart.js:73-76 detaches listeners; :95-97 the #initialized guard skips #createDOM; :166 is the only place listeners are attached. The same pattern exists in all charts (e.g. mini-bar-chart.js:53-66 attaches only when no svg exists yet).
